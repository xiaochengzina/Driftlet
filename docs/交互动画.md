# 交互动画规范

> 管理器 UI 的动效标准：什么时候动、动多久、用什么曲线。改 `src/css/style.css` 的动效或新增任何动画前请先阅读。视觉体系见 `docs/设计系统.md`；本规范的规则目录来自项目本地安装的技能 `.agents/skills/`（emilkowalski），完整版见 `.agents/skills/review-animations/STANDARDS.md`。

---

## 一、什么时候动 / 什么时候不动

动画必须有目的：空间一致、状态指示、解释、反馈、防止突兀变化。「看起来酷」在高频元素上不是目的。按触发频率决策：

| 频率 | 决策 | 本项目实例 |
| --- | --- | --- |
| 每天 100+ 次（键盘动作、面板开关） | **永不加动画** | 全局热键显隐皮肤（无任何过渡） |
| 每天数十次（悬停、列表导航） | 删除或大幅削减 | 选皮肤/切页签 = 纯透明 0.15s，无位移 |
| 偶尔（弹层、toast、对话框） | 标准动画 | confirm 弹层、更新提示、toast |
| 罕见（首次、成功反馈） | 可投入表现力预算 | 安装引导页（网格氛围光 + popIn） |

---

## 二、缓动决策（按此顺序选择，不要自行发挥）

- 入场 / 出场 → **`--ease-out`**（强 ease-out，起步快、显响应）
- 屏上移动 / 形变 → `--ease`
- 悬停 / 颜色变化 → `--ease`
- 恒速运动（spinner、跑马灯） → `linear`
- 拿不准 → `--ease-out`

**UI 上禁用 `ease-in`**：起步慢，恰好拖慢用户盯着看的那一瞬间。

令牌集中在 `style.css` 顶部，新增动画一律引用，不得手写近似曲线：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--ease` | `cubic-bezier(0.4, 0, 0.2, 1)` | 悬停、颜色、屏上移动 |
| `--ease-out` | `cubic-bezier(0.23, 1, 0.32, 1)` | 入场、出场、按压 |

---

## 三、时长预算：UI 动画压在 300ms 以内

| 元素 | 预算 | 本项目取值 |
| --- | --- | --- |
| 按压反馈 | 100–160ms | **0.12s** |
| 悬停/颜色过渡 | 100–200ms | **0.15s** |
| 内容区淡入（选皮肤、页签页） | ≤150ms | **0.15s** |
| 小浮层、toast | 125–250ms | toast 入 **0.25s** / 出 **0.2s** |
| 对话框、弹层 | 200–300ms | popIn **0.2s**；遮罩 fadeIn **0.15s**（设置页 0.25s） |
| 开关滑块 | ≤200ms | **0.18s** |
| spinner | 恒速 | `wizardSpin` 0.8s `linear` 无限 |

---

## 四、物理感规则

- **禁止 `scale(0)` 入场**：现实中没有物体凭空出现。入场起点 = `scale(0.9–0.97)` + `opacity: 0`（本项目 popIn = `scale(0.96) translateY(8px)`）。
- **模态框 `transform-origin: center` 是豁免项**（它本来就该出现在视口中心，不要报成问题）；将来新增触发点锚定的浮层（下拉、气泡）必须从触发点方向缩放。
- **按压反馈**：`:active { transform: scale(0.97) }`，过渡 `transform 0.12s var(--ease-out)`。已覆盖九类按钮：`.win-btn` / `.icon-btn` / `.btn-add` / `.load-btn` / `.action-btn` / `.theme-btn` / `.confirm-btn` / `.cfg-chip` / `.settings-close`（共享 `:active` 规则，`:not(:disabled)` 门控）。**新增可按压按钮**：在自己的 `transition` 末尾加 `transform 0.12s var(--ease-out)`，并把选择器并入共享规则。

---

## 五、可打断性

- 会被快速连续触发、可中途反转的动态 UI（堆叠通知、开关、拖拽）用 **transition**（可从当前状态重定向），不用 `@keyframes`（每次都从零重播）。
- 一次性入场（遮罩、对话框、页面内容）用 keyframes 没问题——它们不会被中途打断。
- toast 是单例替换制（新提示直接移除旧提示重建，见 `src/js/toast.js`），不存在堆叠重排，故保留 keyframes 入场。

---

## 六、性能红线

- **只动画 `transform` 与 `opacity`**（走合成器）；`width`/`height`/`margin`/`padding`/`top`/`left` 会触发布局+重绘，禁用。
- **禁止 `transition: all`**：一律写精确属性列表（本项目既有约定，勿回归）。
- 过渡期的 `filter: blur()` 保持在 20px 以下。
- 复杂变形优先 `clip-path: inset()` 与 `translate` 百分比（相对自身尺寸），不写死像素位移。

---

## 七、无障碍

- 所有 `:hover` 动效挂 `body.hover-ok` 门控（既有约定，见 `docs/设计系统.md`「JS ↔ CSS 契约」）。
- **`prefers-reduced-motion` = 降级而非清零**：保留颜色/透明度反馈与加载 spinner（可理解性），移除位移/缩放类运动。实现 = `style.css` 文件末尾的媒体查询块：同特异性选择器靠层叠顺序覆盖（位移类入场改播 `reducedFade`/`reducedFadeOut` 纯透明帧、hover/按压 transform 置 none）。
- 开关滑块的位移**保留**：12px 级微距、且本身就是状态指示，属「帮助理解」的反馈。
- 新增动效必须自查：开启系统「降低动态效果」后走一遍对应流程。

## 八、模式速查表

| 模式 | 选择器 | 参数 |
| --- | --- | --- |
| 内容区淡入 | `.config-panel` / `.settings-page` → `contentFade` | 0.15s `--ease-out`，纯透明 |
| 遮罩入场 | `.confirm-overlay` / `.settings-overlay` / `.wizard-overlay` → `fadeIn` | 0.15s（设置 0.25s）`--ease-out`，纯透明 |
| 对话框弹入 | `.confirm-dialog` / `.wizard-card` → `popIn` | 0.2s `--ease-out`，scale(0.96)+8px |
| toast | `.toast` → `toastIn` / `.toast-out` → `toastOut` | 0.25s 入 / 0.2s 出，`--ease-out` |
| 按压反馈 | 共享 `:active` 规则（九类按钮） | scale(0.97)，0.12s `--ease-out` |
| 开关滑动 | `.toggle .slider::before` | 0.18s `--ease` |
| 加载 spinner | `.wizard-spinner` → `wizardSpin` | 0.8s `linear` 无限 |
| 皮肤卡片 hover | `.skin-card:hover` | translateY(-1px)，0.15s `--ease` |

## 九、改动后验收清单

1. **慢放检查**：DevTools Animations 面板逐帧看，或临时把时长 ×3 确认曲线、transform-origin、多属性同步无漂移。
2. **截图自查**：用 `docs/设计系统.md`「视觉验证工作流」的无头截图（`--virtual-time-budget` 必须加，让动画播完）。
3. **reduced-motion** 开启后过一遍主要流程：反馈仍在、位移消失。
4. **高频路径复审**：本次改动涉及的交互每天可能被触发多少次？对上频率表再确认一次该不该动。
5. `transition` 是精确属性列表；新曲线/新时长先查令牌表，没有再从本规范补令牌，不手写出没的数值。
