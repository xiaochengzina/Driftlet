## 1. 项目是什么

**Driftlet 是 Windows 桌面挂件（皮肤）平台**：把网页以桌面小部件形式呈现——透明窗口、无边框、置顶或贴在桌面，由管理器统一装载、配置与编排。第三方创作者用纯 HTML/CSS/JS 写皮肤，经注入桥调用本机能力（系统信息、媒体、剪贴板、文件等）。

- **技术栈**：Tauri v2（Rust 后端）+ WebView2（系统运行时，不捆绑）+ Vite + 原生 JavaScript 前端（**刻意不用任何前端框架**——管理器是单页工具界面，框架的运行时成本与构建复杂度不划算；公共件集中在 `src/js/dom.js`，不要再复制第三份）。
- **许可**：GPL v3；免费开源禁止倒卖（用户协议十条详见安装器许可页 / 关于页）。
- **当前版本**：1.2.6。**版本号四处一致**（硬性约定）：`package.json` / `package-lock.json`（两处）/ `src-tauri/Cargo.toml` / `src-tauri/tauri.conf.json`，外加 CHANGELOG 定稿节标题（仅开发仓库——公开仓库的变更记录由 releases 页承载，发布时摘节 + 英文现译）；公开仓库 Release 工作流有版本号闸门脚本。
- **数据布局 = 便携模式**：一切随安装目录走——皮肤 `<安装目录>\skins\`、全局配置 `<安装目录>\config\config.json`、更新下载 `<安装目录>\update\`、内置皮肤资源 `<安装目录>\bundled-skins\`；安装目录不可写（如 Program Files）时整体回退 `%APPDATA%\com.driftlet.app\`（旧版 %APPDATA% 配置首启自动迁移）。WebView2 用户数据在 `%LOCALAPPDATA%\com.driftlet.app\`。
- **双仓库分工**：开发仓库（本仓库）全量留存；公开仓库（xiaochengzina/Driftlet）按排除清单同步（`docs/` 为白名单制：皮肤开发指南、关键机制、本文档等公共文档双版过去；设计规范/实机清单/发布流程/proposals/已知问题等内部文档不过去）。流程见 `docs/公开发布流程.md`（仅开发仓库）。

## 2. 进程与窗口总览

**进程模型**：单 Rust 宿主进程 + 每个 WebView2 窗口各自一套渲染进程树。管理器关窗即销毁（回收约 80MB 渲染进程；无皮肤加载时整个 WebView2 进程树退出，仅剩 Rust 宿主），托盘唤回时重建（页面重载约 1 秒）——隐藏挂起路线（WebView2 TrySuspend）已实机证伪，勿再投入（见 docs/已知问题.md）。

**窗口清单**：

| 窗口 | label | 创建者 | 备注 |
|---|---|---|---|
| 管理器 | `main` | 启动即建；销毁后由托盘/右键「打开皮肤配置」/双击 .dskin 重建 | 960×640（最小 640×460），无标题栏原生窗框 |
| 皮肤窗 | `skin-<id>` | 加载/唤回时 `window/factory.rs` 创建 | 无边框 + Win32 子类；网页皮肤（entry 为 URL）除外 |
| 日志窗 | `log` | 设置页「高级」`open_log_window` | 独立页面 log.html，主题/语言烘焙进 URL query |

**capabilities 按窗口拆分**（`src-tauri/capabilities/`，三文件）：`default.json` 只挂 `"main"`（core:default + 窗控最小集：minimize/toggle-maximize/internal-toggle-maximize/start-dragging/hide/close/show/unminimize/set-focus）；`log.json` 挂日志窗；`skin.json` 挂 `"skin-*"` 且 **permissions 为空**——皮肤页面是第三方网页，不授予任何 Tauri 核心/插件权限，只能经注入桥调后端命令（自定义命令不受 capabilities ACL 约束，由 Rust 侧闸门把关）。tauri.conf 的 CSP（`default-src 'self'` 等）只作用于应用协议页，皮肤页响应无 CSP（共享源现实见 §6）。

**单实例**：`tauri-plugin-single-instance` 必须保持在插件列表**第一位**注册——第二实例把 .dskin 路径/唤回请求转发给首实例（热路径），冷启动双击走命令行参数（§9）。

**托盘**：左键 = 显示/隐藏管理器，右键 = 菜单；托盘创建失败时关窗降级为直接退出（不留无窗残留进程——`AppState.tray_ok` 判定）。

## 3. 前端架构（src/）

**决策：无框架原生 JS**。管理器 = 多页 Vite 构建（`index.html` 管理器 + `log.html` 日志窗，`vite.config.ts` 的 rollupOptions.input；dev 端口 1420 strictPort）。CSS 集中在 `src/css/style.css`（设计令牌 + 组件，规范见 docs/设计规范.md，仅开发仓库）。

**`src/js/` 模块职责**：

| 模块 | 职责 |
|---|---|
| `app.js` | 主入口：启动序列、导航/侧栏骨架、路由（皮肤库/编辑器/各面板） |
| `api.js` | Tauri IPC 封装（invoke 薄层 + 事件 listen 助手） |
| `dom.js` | 共享 DOM 小件：`esc`/`escAttr`（HTML 转义）、`confirmDialog`（Esc/遮罩/焦点落取消、danger 红/primary 蓝）、`bindEsc`、`closeOnMaskClick`、`bindHotkeyCapture`、`dispName` |
| `i18n.js` | 界面语言 zh-CN/en：扁平点分键字典（中英各 372 键，严格对等）、`t(key, params)` 占位替换（**不转义**，HTML 场景调用方先 `esc()`）、`initI18n` 启动读后端、`applyLang` 切语言写回并重绘 |
| `skin-list.js` | 皮肤库列表（分组折叠、徽标三档 hidden/loaded/unloaded、预览图、占位图标） |
| `skin-editor.js` | 皮肤编辑器：窗口页 + 皮肤设置页（23 种控件渲染 `renderCustomSettings`/`bindCustomSettings`）+ 操作区；全部实时同步监听汇聚于此 |
| `layouts.js` | 布局方案面板（保存/应用/覆盖/重命名/删除；覆盖有确认弹窗） |
| `settings.js` | 设置面板（通用/高级页签：主题、语言、自启、热重载、更新设置、日志入口等） |
| `install-wizard.js` | .dskin 安装引导页（四态：检查→确认→安装→完成/失败；`_gen` 代际计数作废旧异步结果） |
| `perms.js` | 权限声明渲染单一口源（12 权限三档配色 chips，向导/编辑器/导入审查共用） |
| `about.js` | 关于面板（版本/公开仓库/用户协议全文/手动检查更新） |
| `update-check.js` | 启动更新检测与更新弹窗（进度条、通道指示、立即安装/前往下载） |
| `focus.js` | 专注模式面板（状态卡、动作档、全屏自动、白名单） |
| `toast.js` | 全局单例提示（新替换旧，向上淡出移除——勿再各自 appendChild） |
| `log.js` | 日志窗页面（先 listen 再拉取、seq 增量合并、按皮肤过滤） |

**i18n 纪律**：界面文案一律走 `t()` 字典（中英双版同键）；皮肤的 schema 文案（label/description/group/options）由作者提供，不经过本模块。**中英键数量必须对等**（目前 372=372）。

**主题**：CSS 变量挂 `:root`（浅色默认）与 `:root[data-theme="dark"]`；主题选项按钮自带 `data-theme` 属性供 JS 读取。

**AppState 关键字段**（`lib.rs`）：`registry`（皮肤窗注册表）、`config: Mutex<AppConfig>`、`config_dir`/`skins_dir`、`exiting`/`tray_ok: AtomicBool`、`pinner`、`main_thread_id`（Win32 子类必须窗口所属线程）、`pending_package`（双击 .dskin 待装包，前端幂等拉取）、`pending_open_config`（管理器销毁时右键「打开皮肤配置」的暂存）、`hotkey_error`（热键注册失败待 toast）、`language` 镜像、`toggle_item`/`skin_vis_items`（托盘勾选件句柄）、三把锁。

**锁模型与锁序**（勿回归）：`lifecycle_lock`（tokio，串行 load/unload/reload/reset 与 skin_api 生命周期命令——「查存在→注册」非原子）→ `install_lock`（tokio，串行包安装/卸载/备份导入导出/重载全部）→ `settings_lock`（std，settings.json 双写者与目录替换互斥）。guard 必须 Send 才跨 .await；无反向路径，无 ABBA。**批内并发**：`run_skins_concurrent`（op 参数化 Load/Unload/Reload）把「锁内一串 await」改成「锁内一批并发」（启动自载/专注模式进出/布局套用/备份导入/重载全部/组批量共用）——多皮肤近似同批亮相，串行逐窗是「一个接一个出现」观感的来源；并发只在同批之间，两批操作仍不交错。另：**持锁守卫不得跨「会再取同一把锁」的调用**（std Mutex 不可重入——持 config 守卫调 rebuild_tray_menu 曾死锁）；**全域 Mutex 中毒恢复**一律 `.lock().unwrap_or_else(|e| e.into_inner())`（持锁路径 panic 后服务继续）。

**命令注册与策略表（policy.rs，全应用攻击面单一事实源）**：全部 **130 条** IPC 命令在 `COMMAND_POLICIES` 登记闸门档——八档：**ManagerOnly（68）** / LogWindow（2）/ Perm（38）/ AnyPerm（仅 open_external，1）/ ControlTarget（7）/ CallerSkin（8）/ SkinLabel（4）/ Ungated（2）。表不改变运行时行为（闸门在函数体）；价值在三个完备性测试：`policies_complete_and_marked`（表 ↔ lib.rs generate_handler! 清单双向同集合、函数体含登记档位的闸门标记文本）、`perm_const_names_resolve`（权限常量名锚回真实常量）、`gate_distribution_snapshot`（各档计数钉住）。**新命令纪律：函数体首行放闸门 + 表内登记一行，否则 cargo test 红**；新增命令模块需在 `policy::tests::module_source` 登记。

**vendored 补丁**（`src-tauri/vendor/`，`[patch.crates-io]` 指向，升级依赖必须保留，勿覆盖）：① `tauri-runtime-wry`——杀进程不派 WM_DESTROY 的死句柄 `Destroyed` 补丁（NOTE(driftlet) 标注）；② `tray-icon`——0.24 的垃圾掩码 HICON 修复 + `TaskbarCreated` 路径 `NIM_DELETE` 安静变体（explorer 重启后旧图标已死，删除必然失败勿弹错）。另有 `build.rs` 的 comctl32 v6 清单方案（`cargo test` 的测试 exe 曾因清单内嵌失败 `0xc0000139` 启动即崩——解法勿拆散）。

## 5. 皮肤模型

**皮肤 = 独立文件夹**，至少 `skin.json`（元信息/窗口默认/设置 schema）+ `index.html` + 资源。打包形态 = `.dskin`（zip 改扩展名，skin.json 在根目录或唯一一级子目录）。

**skin.json schema**（`skin/types.rs` 强类型；完整参考 = 皮肤开发指南 §2/§4）：

- 顶层：`id`（kebab-case，打包必填；文件夹直装缺省按文件夹名 slug 兜底）、`name_zh`/`name_en`、`version`、`author`、`description_zh/en`、`entry`（默认 index.html；拒 `../\\/:`；http(s) URL = 网页皮肤）、`permissions`（12 种见 §8）、`min_host_version`（安装期提示不拦截）、`refresh_seconds`（仅网页皮肤，≤24h）。
- `window` 默认值：width/height（300/200，钳 1..10000）、transparent（true）、always_on_top/on_desktop（false/true）、resizable、zoom（1.0∈[0.5,2.0]）、opacity（1.0∈[0.1,1.0]）、edge_snap/snap_gap（皮肤可声明出厂吸附，≤200px 归一化）。
- `settings[]`：23 种控件（boolean/number/stepper/text/longtext/time/date/palette/select/multiselect/radio/weekdays/font/slider/timerange/tasklist/todolist/datetime/password/datetasklist/file/directory/gpu_adapter）+ group 分组 + description。**新增控件类型需同步四处**：`types.rs` 的 SkinSettingKind、loader 校验、`skin-editor.js` 渲染/绑定、pack-skin 镜像（外加文档与 controls-demo）。
- **文案字段对称命名 + 旧键 alias（勿回归）**：`name_zh/name_en`、`label_zh/label_en`、`group_zh/group_en` 等成对；旧无后缀键（name/label/group/description）经 serde alias 继续被接受。显示回退 = 界面语言优先、缺失回退另一语言（无 bilingual 开关，已移除）。

**加载校验与归一化**（loader.rs）：skin.json ≤1MB；id 黑名单 Windows 保留设备名（con/prn/aux/nul/com1-9/lpt1-9，按基名判）；**window 默认值统一在 load 归一化**（宽高钳/opacity 回落/zoom clamp/refresh ≤24h——`opacity:0 + 置顶 + 巨尺寸` = 隐形置顶全屏吃点击窗口，安装向导不展示 window 默认值，必须在 load 拦）。

**皮肤身份 = id，但 id ≠ 文件夹名**（勿回归）：按 id 定位目录必须先扫描解析（`find_skin_dir`），不要直接 `skins_dir.join(id)`；URL 首段也是磁盘文件夹名。扫描按 id 去重、后到者告警跳过；同 id 不同文件夹名的遮蔽在安装前拦下。

**运行时配置**（`SkinRuntimeConfig`，存 config.json 的 `skin_settings[id]`，按 id 归属与皮肤文件解耦）：几何/层级/开关项。**Option 跟随模式**：resizable/zoom/edge_snap/snap_gap 为 `Option`——None = 跟随 manifest 默认（老配置升级自动跟随作者新声明），Some = 用户显式选择（显式永远优先）；**下发管理器面板前必须在 get_skin_detail 解析成有效值**（面板显示脱节事故：屿族 manifest 声明开/20px，裸 None 被前端渲染成关/0）。持久化结构新增字段必须带 `#[serde(default)]`（Option 除外）——漏加 = 所有老 config.json 解析失败被当损坏重置，炸伤半径是全部皮肤数据（仅 .bak 兜底）。磁盘上已不存在的皮肤，其配置残留启动时统一清理（`prune_stale_entries`）。

**用户设置值**在皮肤文件夹 `settings.json`（schema 默认值 + 覆盖值合并；缺失→空、容忍 BOM、损坏→改名 .bak、原子写；「重置」= 删文件；应用永不重写 skin.json；覆盖值只在类型匹配 schema 时被采用）。**password 类型值不烘焙进页面**（skin:// 全皮肤同源，注入会被其他皮肤抓）——`baked_settings_json` 恒置空串，皮肤经 `skin_get_setting` 按窗口身份下发。**settings.json（含 .bak/.tmp）永不经 skin://**（双重拦截：URL 文件名 + canonicalize 后真名复核，防 8.3 短名 `SETTIN~1.JSO` 与 ADS `::$DATA` 绕过）；assetProtocol 已整块删除（其 scope 按前缀放行拦不住单文件，曾泄露 settings.json）。**settings.json 不进分发包**（pack-skin 排除）。

**内置屿族六皮肤**（isles-countdown/calendar/clock/monitor/weather/timer）：源在 `examples/`，经 bundle.resources 打进安装包落 `bundled-skins/`；**一次性种子**（`AppConfig.bundled_skins_seeded`）——补缺不覆盖（用户删过的不复活、自己更新的不被覆盖），老版本升级同样首跑一次。开发期 `copy_example_skins` 只同步 examples/（demos/ 已停同步）。

## 6. 皮肤运行时：skin:// 协议与注入桥

皮肤页面与资源经 `skin://` 自定义协议加载（`skin/protocol.rs`）。它的职责不是限制网络，而是四个控制点：

1. **桥接注入**：serve HTML 时烘焙 `__DESK_PP__`（settings/opacity/positionLocked/resizable/language/theme/hostVersion + 右键接管 + 边缘缩放热区 + console hook），并挂推荐别名 `window.driftlet`（同一对象，永久兼容）。**窗口态必须经入口 URL query（opacity/locked/resizable）原子送达**——不要用创建后 eval 恢复（与页面加载赛跑，曾致置顶↔贴桌面切换闪烁）；运行时切换才走 eval（页面已加载无竞态）。设置 JSON 序列化进 `<script>` 前必须把 `</` 转义为 `<\/`（防 `</script>` 提前闭合）。注入脚本保持纯 ASCII（页面 charset 不受我们控制）。
2. **用户数据隔离**：settings.json 一律 404（双重拦截，见 §5）。
3. **路径沙箱**：canonicalize + 前缀校验，皮肤只能读 skins_dir 内文件；屏蔽 dev/prod 路径差异。
4. **`__fs__` 保留端点**：`http://skin.localhost/__fs__?path=<percent 编码绝对路径>`——声明 `file_system` 的皮肤用 URL 直引外部文件（图/视频不进 JS 内存；base64 通道适合数据处理）。未声明一律 404；UNC 一律拒绝（防 SMB/NTLM 外发）。

**URL 改写（Windows）**：WebView2 不支持非标准协议的子资源加载，wry 把导航 `skin://localhost/...` 改写为 `http://skin.localhost/...`，请求侧按 host 回映射手册。文档与皮肤一律写相对路径（绝对形态首段 = 磁盘文件夹名）。

**网络现实**：皮肤页是完整 Chromium——仅 `http://skin.*` 被拦截，外部 http/https 直连真实网络；皮肤页响应无 CSP。设计前提：**皮肤 = 能联网的本机代码**，信任模型按此对待（安装引导逐条展示权限）。

**边界（已知暴露面）**：所有皮肤共享单一源 `http://skin.localhost`——同源策略不隔离皮肤（A 可请求 B 的普通资源；仅 settings.json 被拦）。password 不入页面正是为此。若日后限制皮肤联网，落点在协议层。

**网页皮肤（entry 为 http(s) URL）**：窗口直接 `WebviewUrl::External` 加载站点，不走 skin:// 与桥注入——页面上没有拖动区/右键菜单/命令通道（tauri 的 remote-origin 守卫拦远程源命令）；站点登录态走 WebView2 cookie 罐天然持久。`refresh_seconds` 定时刷新仅此形态。

**桥事件面（皮肤侧 DOM 事件）**：`desk-setting-changed`（设置值变更）、`desk-language-changed`/`desk-theme-changed`（界面语言/主题）、`desk-window-config-changed`（窗口属性，detail={key,value}）、`desk-skin-message`（皮肤间广播，detail={channel,from,payload}）、`desk-skin-menu-item`（自定义右键菜单项点选）。**管理器方向事件**：`skin-moved`/`skin-resized`（拖拽防抖通道）、`window-config-changed`（窗口属性广播，见 §7 数据流）、`skin-setting-changed`（皮肤写设置→管理器）、`skins-visibility-changed`（显隐漏斗）。

**console 洪防（桥侧，IPC 洪泛才是真实成本）**：console.log/info/debug/warn/error 包装转发 + error/unhandledrejection/securitypolicyviolation 捕获；队列 250ms 一次 flush、整批一次 invoke、相邻重复合并 (xN)、每 flush ≤30 条、队列硬顶 300、单条预截 1200 字符、溢出合成 flood guard warn；hook 内部异常静默吞（绝不递归调 console）。批量通道 `skin_console_log`（SkinLabel 身份，每批 ≤60）不走 caller_skin（它全量扫盘，高频通道不能每批扫一次）。

## 7. 窗口机制（Win32 层）

### 7.1 无边框机制（四防线，勿回归）

皮肤窗口「时有时无经典标题栏」的根因与防线：① `SetWindowSubclass` **必须在窗口所属线程调用**（load/reload 在 spawn_blocking 工作线程跑时跨线程调用静默失败——经 `run_on_main_thread`）；② **禁止 `DwmExtendFrameIntoClientArea(-1)`**（玻璃延伸把 DWM 边框画进整个客户区）；③ `SWP_FRAMECHANGED` 只在样式真脏时发（无条件发 = 不停给边框出现的机会）；④ tao 的 `to_window_styles()` 对顶层窗口永远带 `WS_CAPTION` 且任何 set_window_flags 都会经它——vendored 补丁与自家子类（`force_frameless`、WM_STYLECHANGING/CHANGED 三处摘位）负责剥净。

### 7.2 贴在桌面（desktop.rs pinner）

- **Win+D 的真实机制**：皮肤**不会被最小化**（无边框样式剥掉 WS_MINIMIZEBOX，minimize-all 只针对可最小化窗口）；皮肤「消失」是 **z 序遮挡**。
- **现行方案 = 持续 z 序贴附**：250ms 值守环校验每个贴桌面皮肤是否就位（判定 = **紧下方是图标宿主或另一个贴桌面皮肤**——多皮肤时严格的「正好在宿主正上方」不可能同时成立）；偏了就修正。**故意无 Show Desktop 状态机、无 helper 窗口**——每 tick 重验即自愈（旧状态机曾在 restore 后卡死、explorer 重启后自愈）。
- 图标宿主查找**不做版本启发式**（Progman 直接含 DefView 与顶层 WorkerW 含 DefView 两种形态都认）。
- z 序必须显式放在图标窗口**正上方**——低了桌面 ListView（SysListView32）吞掉所有点击。
- 贴桌面时置 `WS_EX_TOOLWINDOW` 清 `WS_EX_APPWINDOW`（任务栏/Alt+Tab 不可见，双保险）；取消时**两个 bit 都清**（曾只清其一）。z 序顶置时回退 HWND_TOP；修复前校验窗口进程归属（hwnd 被系统复用时绝不动手）。
- 「置顶」与「贴桌面」二选一必居其一（默认贴桌面）；配置加载把「同开/同关」归一为贴桌面（`normalize_mode_flags`，含 wallpaper_layer 迁移）。

### 7.3 位置锁定

开关 = 桥内 `__DESK_PP__.positionLocked`；建窗时 URL query `locked=1` 烘焙（勿改回创建后 eval）；运行时切换走 `set_skin_position_locked` 的 eval；锁定 CSS 统一 `#desk-lock-style` id。

### 7.4 皮肤拖动与右键菜单

- 不再依赖 `-webkit-app-region: drag`（Windows 把它当标题栏、右键弹系统菜单）。`.drag-region` 由注入脚本绑 pointerdown → `start_skin_drag` 进系统模态移动循环。**按下点在交互元素（`button/input/select/textarea/a/label/[contenteditable="true"]`）上必须跳过**——模态循环在 pointerdown 捕获鼠标，配套 pointerup 被吃、DOM click 永不触发（1.0 时 controls-demo 无窗口内按钮，bug 潜伏至出现带按钮皮肤才暴露）。
- 右键 = 自绘原生菜单（打开配置/刷新/**窗口行为快捷开关段**（置顶/禁止拖动/穿透/拖拽缩放/边缘吸附，MF_CHECKED 勾选态 = 开菜单时快照，点选分发到对应 `set_skin_*_impl`）/自定义项段（皮肤 `skin_set_menu_items` 注册，≤8 条、id≤32、label≤40、勾选态、双语标签，卸载清除）/隐藏/卸载）。WebView2 默认菜单 `SetAreDefaultContextMenusEnabled(false)` 关闭——建窗时 WebView2 未就绪首调必败，由重试线程（~6s）+ 5s 维护定时器兜底，**不要改回创建后单次调用**。
- 右键事件冒泡末端查 `defaultPrevented`——皮肤在某元素上自行 `oncontextmenu` 处理（stopPropagation + preventDefault）则宿主不弹菜单。

### 7.5 边框拖拽缩放（resizable，三态）

- **热区必须在 JS 桥接层实现，不能靠子类 WM_NCHITTEST**——WebView2 子窗口铺满皮肤窗，父窗口永远收不到命中测试（曾按此实现，无边框光标也拖不动，已回退）。
- 链路：有效值 → 建窗 URL 烘焙 `resizable=1` → 桥脚本绑边缘 6px 热区（光标形态 + `start_skin_resize` 合成消息，与拖动同机制）→ 模态缩放循环。运行时开关 = `set_skin_resizable` eval 调 `__DESK_PP__.setResizable(on)` + 边框提示层（`#desk-resize-frame` 四边 4px 黄黑斜纹）。
- **尺寸/位置持久化走后端 Moved/Resized 事件**（勿移回前端——前端监听只在配置页打开时注册，曾致「面板没开时拖动不保存」）：物理 ÷ **建窗锁定的快照尺**（`SCALE_SNAPSHOTS`：建窗时物理客户区 ÷ 逻辑宽——曾用「当前物理 ÷ 已存逻辑」，resize 期间分子随事件变、换算恒等旧值永不落盘）；内存即改 + 500ms 防抖写盘（`debounced_config_flush`）+ `emit_to("main", "skin-moved"/"skin-resized")` 刷新面板输入框（面板回环事件值相同跳过不写）。
- 子类 `WM_GETMINMAXINFO` 设最小 60×40（DPI 缩放）必须保留——模态缩放循环无论谁触发都读它。
- 配置值**一律逻辑像素**（创建/设置/事件回读同一约定）；任何路径把配置值套进 PhysicalSize/PhysicalPosition，DPI≠100% 时实际尺寸与面板不一致、reload 后「还原」。

### 7.6 边缘吸附（snap.rs）

- **挂点 = 子类 `WM_MOVING`**（勿用 Moved+set_position——回环触发且轨迹不平滑）。系统模态拖动循环每步把待定 RECT 传进来，就地改写。
- **吸附状态按 HWND 登记**（`SNAP_WINDOWS`，子类回调只有 HWND 可用）：建窗 upsert、销毁 unregister（HWND 会被系统回收复用，残留会把无关窗口误当候选）。
- **吸附 = 纯距离判定**：X/Y 各轴先算屏幕候选，|delta| ≤ 阈值（`SNAP_THRESHOLD`=10 逻辑 px 按窗口 DPI 换算物理）就用屏幕（屏幕优先于窗口，哪怕窗口更近）；都不在阈值内才取 |delta| 最小的窗口候选（四缘对齐 + 相邻贴合，要求垂直方向重叠或间距 ≤ 阈值，防幻影吸附；超大窗口排除屏幕候选）。
- **慢拖脱开 = 原始拖动轨迹**：系统 WM_MOVING 提议矩形是相对「上一步写回值」的增量——贴边后慢速拖动每步仍落阈值区内会被「粘死」。吸附判定改为针对按鼠标增量累积的原始轨迹，慢拖拖出阈值区即平滑脱开（实机注入轨迹验证，含回归测试 `slow_drag_detaches_once_raw_leaves_threshold_zone`）。**逃逸窗口（松手再拖 1 秒免吸附）已随之移除，勿再加回**；精细微调用「窗口」页坐标输入。
- 间距 `snap_gap`（逻辑 px，clamp 0–200=`MAX_SNAP_GAP`）对屏幕边缘与窗口相邻贴合都生效（对齐类候选不含间距）；Option 跟随模式见 §5。

### 7.7 鼠标穿透（已恢复——当年根因是自家子类摘位，不是样式位无效）

- 机制：tao `set_ignore_cursor_events(true)` 置 `WS_EX_TRANSPARENT|WS_EX_LAYERED`。**当年两轮失败的真根因**：自家无边框子类三处（force_frameless/WM_STYLECHANGING/WM_STYLECHANGED）无条件剥掉这两位，5s 自愈定时器再兜底回剥。
- 命门：穿透窗**按 HWND 登记**（`PASSTHROUGH_HWNDS`），三处摘位逻辑对登记窗改用保留掩码；**顺序命门：先登记再调 set_ignore_cursor_events**（tao 经 execute_in_thread 落 SetWindowLongPtr 触发样式消息，未登记就被剥回）；销毁路径必须摘除登记（HWND 复用纪律同吸附）。
- 风险敞口：「LAYERED 破渲染」无法对所有环境一次证伪——逐皮肤开关、默认关即熔断。历史探测结论（tools/win32-probes/ctprobe.ps1，勿再试）：顶层非分层 TRANSPARENT 被命中测试无视；WorkerW 兄弟间透明命中跳过仅同线程有效；子类返回 HTTRANSPARENT 路线死。
- `click_through` 默认关；`set_skin_click_through` 已加载原位翻转、未加载仅持久化。

### 7.8 DPI、虚拟显示器与壁纸层

- **黑底病根 = 虚拟显示器 DPI 不一致致 WebView2 视觉树错位**（GameViewer/向日葵等 IddCx 虚拟屏 + Win10 21H2 @125% 实测定论）：DPI 上报互相矛盾时 WebView2 光栅化尺错位。平台侧检测处置见代码；**皮肤作者侧**：尺寸一律逻辑像素（§7.5）。
- **壁纸层已移除**（SetParent 进 WorkerW/Progman 子窗 = 图标下壁纸上、鼠标物理免疫）：依赖全套未文档化内部结构（Progman/WorkerW/DefView 类名、0x052C 消息），过于脆弱整体废弃，由贴桌面 + 鼠标穿透承接需求。旧配置 `wallpaper_layer:true` 由 normalize_mode_flags 迁移为贴桌面（字段 deprecated 仅为迁移保留）；壁纸表面黑破洞由一次性强制重绘兜底（`repaint_wallpaper_surfaces_once`）。**保留物**：杀进程不派 WM_DESTROY 的死句柄 Destroyed 补丁（vendored tauri-runtime-wry）。

### 7.9 预览截图（capture.rs）

- `capture_skin_preview` **必须保持 async fn**——非 async 命令在主线程执行，而截图要 `recv_timeout` 阻塞等 WebView2 CapturePreview 完成回调（同步会卡死主线程；Tauri 2 同类约束还适用于 run_command、SMTC 三条、open_log_window 建窗等）。
- 走 `ICoreWebView2::CapturePreview`——**不要改回 PrintWindow+GDI**（alpha 未定义、透明皮肤黑底、遮挡/贴桌面/最小化全挂）。
- **落盘前降采样最长边 ≤640px**：管理器卡片显示区只有 226×96 CSS px，全尺寸 PNG 解码 ~8MB RGBA 每张驻留渲染进程。失败一律回退原图落盘（偏大只是内存取舍，缺失打断「装完即见预览」）。创作者自带 preview.png 走第二防线：安装/打包校验最长边 ≤1280px（只读文件头 PNG IHDR/JPEG SOF；头解析不出放行），pack-skin 有手工镜像（改任一侧必须同步并重建 exe）。

### 7.10 窗口图标

tao 0.35.x 的 `RgbaIcon::into_windows_icon()` 与 tray-icon 垃圾掩码 bug 同款代码；tauri-codegen 会把 icons/icon.ico 烘为 default_window_icon 套用每个窗口——任务管理器/Alt+Tab 会取到垃圾掩码 HICON。故 `run()` 显式 `set_default_window_icon(None)`；窗口图标改由 `apply_window_icon()` 对多尺寸 icon.ico 直接 `CreateIconFromResourceEx` + `WM_SETICON` 显式设置（管理器窗与日志窗都调）——exe 资源回退**并不覆盖**任务栏按钮/悬停预览/Alt+Tab（实测默认图标），不能依赖。**不要**给窗口调 `.icon()/set_icon()`，不要移除屏蔽行。托盘图标另行逐尺寸 PNG（tray.rs 内嵌 16–48 共 7 尺寸，tools/make-tray-icon.py 参数化几何逐尺寸渲染，不合成 ico、不大图缩小）。

### 7.11 数据流与出屏救回

- **拖动位置保存必须留在后端 Moved 事件**（见 §7.5）。窗口属性变更广播 = 单一汇聚点 `emit_window_config_changed`（**勿旁路**）：任何修改窗口属性的路径（管理器面板/右键快捷开关/皮肤自控 `skin_set_window_config`）都经 `set_skin_*_impl` 落地从而必经该函数——它**双发**：`emit_to("main", "window-config-changed", { skinId, key, value })`（不问加载态，打开中的编辑器由 skin-editor.js 监听就地同步；正在编辑的输入框焦点保护不冲掉）+ 皮肤已加载时 eval 派 `desk-window-config-changed`。事故依据：事件曾只发皮肤侧——右键切了吸附开关而「窗口」页勾选不变。完备性由源码扫描测试 `window_config_setters_all_broadcast` 钉住（10 个 impl 全广播，漏即红）。拖拽/边框缩放走 Moved/Resized 防抖通道不经此。
- **完全出屏皮肤救回**（拔外接屏/DPI 拓扑变更后皮肤落在所有显示器之外）：`factory::offscreen_target` 判定——与**所有**显示器工作区（物理像素）都不相交才算出屏，**部分出屏一律不动**（多屏拼接缝、刻意半掩合法）；出屏则移回主显示器工作区左上 +24px（走 Moved 防抖落盘）。两个挂点：lib.rs 5 秒维护定时器 `rescue_offscreen_skins`（自愈最迟 5 秒，启动自载被首 tick 覆盖，无需 WM_DISPLAYCHANGE 钩子）+ 配置页「复位到屏幕内」按钮 `bring_skin_onscreen`。探针 = 被判定皮肤窗自身枚举显示器（勿借管理器窗——它「关窗即销毁」常态不在，曾致救回环空转，2026-09 审查 A2）。

### 7.12 管理器/日志窗窗框与行为约束（前端侧）

- **无标题栏原生窗框**：`decorations(false)` 建窗后 `apply_native_frame` 三件套——样式剥 WS_CAPTION 加回 WS_THICKFRAME|WS_MINIMIZEBOX 等、标题栏区域自绘（拖动经 tauri 注入 drag.js 的 `data-tauri-drag-region="deep"` + `plugin:window|start_dragging`——default.json/log.json 须授 `core:window:allow-start-dragging`，主窗另授 allow-internal-toggle-maximize，曾长期缺失致「标题栏拖不动」；皮肤窗走 start_skin_drag 无 ACL 面）、圆角随系统（Win11 DWM 自动圆角，Win10 方角——产品决定；曾试「透明窗 + CSS border-radius」路线废弃）。**`apply_native_frame` 内含 SetWindowSubclass，必须经 `apply_native_frame_on_owner_thread` 分发到主线程**（跨线程静默失败 → tao 对无边框窗的 NCCALCSIZE 归零无人拦截 → DWM 不画框、圆角消失——皮肤右键唤出管理器曾踩中，右键路径跑在 tokio worker 而托盘路径在主线程，故只有右键唤出丢圆角），5 秒维护定时器 `ensure_native_frame` 幂等兜底。探针：tools/win32-probes/ 的 focus-frame-probe.ps1 / manager-focus-frame.ps1（仅开发仓库）。
- **`[hidden]` 属性 vs 作者 display（已复发四次，防第五次）**：UA 样式表给 `[hidden]` 的只是 display:none，任何作者规则 display:block/flex 都优先——需要隐藏的元素用专用类或内联样式，别信 hidden。
- 窗口隐藏→重显后按钮残留 :hover（WebView2 收不到 mouseleave，按最后已知光标位置重算）——合成事件清不掉（非可信输入），只有真实 pointer 移动能刷。
- **调色板屏幕取色 = 不提供，勿再投入（两路全灭实证）**：原生 `<input type="color">` 面板吸管在 WebView2 失效（实机反馈一）；独立 EyeDropper API 按钮在运行时 152 即调即 AbortError（实机反馈二）。两路全灭，等常青运行时自修。
- 皮肤窗 Alt+F4 = 隐藏不是关闭（WM_CLOSE → CloseRequested → prevent_close + hide + 托盘勾选同步）；**程序化关闭必须登记 `INTENTIONAL_CLOSES`**（卸载/重载/退出汇聚 `close_skin_window_nowait`，close 前登记 label，事件处理消费后放行；close 失败撤销登记；建窗防御性清残留）——vendored tauri-runtime-wry 中 `close()` 与用户 Alt+F4 同走 on_close_requested，CloseRequested 不带关闭原因。
- **`close()` 返回 ≠ label 已释放**：destroy_skin_window 里 close() 后 webview 还要几 ms 才真销毁，紧接同 label 建窗报 "already exists"（右键刷新曾稳定复现「卸载后回不来」）——close 后必须轮询/事件确认再重建。

### 7.13 皮肤入场/出场（淡入淡出）

皮肤窗口的亮相/离场 = 淡入淡出（入场 180ms / 出场 150ms，均 ease-out），走**页面内容透明度**（`documentElement` 的 CSS opacity，与「不透明度」设置同一通道；窗口级 WS_EX_LAYERED 透明度会破坏 WebView2 合成，不用）。三个落地面：建窗入场是**烘焙/注入**（本地皮肤 = 桥 CSS 纯 CSS 关键帧 `deskFadeIn`，不依赖 JS；网页皮肤 = `initialization_script`）；运行时显隐 = `factory::show/hide_skin_window_fade`（show 后 eval 淡入到当前有效不透明度；hide 先淡出再延迟落地，`FADE_GENS` 代际守卫防「淡出中被唤回/重建后迟到 hide 误落新窗」——代数单调递增永不重置，且递增有两个锚点：淡出起点 fade_out_for_destroy + 销毁点 close_skin_window_nowait，缺一即有「二次布防」洞）；销毁 = `fade_out_for_destroy` 阻塞等淡出再走 `destroy_skin_window`（退出路径不淡出）。全部显隐路径（管理器按钮/托盘勾选/热键/Alt+F4/皮肤右键「隐藏皮肤」/skin_hide·skin_show/专注模式隐藏档/布局显隐恢复）都经这两个助手；系统「减弱动画」（prefers-reduced-motion）开启时全部跳过动画直接落定。时长锚点 = `skin::types::FADE_IN_MS/FADE_OUT_MS`（四处共用，勿散落字面量）。详见关键机制「皮肤入场/出场（淡入淡出）」。

## 8. 皮肤后端接口（skin_api）与安全模型

### 8.1 闸门模型（桥直通，无命令白名单）

`__DESK_PP__.invoke` 直接转发 `__TAURI_INTERNALS__.invoke`——任何注册进 invoke_handler 的命令皮肤都能调。因此**敏感命令必须自带权限校验**，身份只认窗口 label：

- `require_manager`——管理器命令（64 条）皮肤窗口调用一律拒绝「该命令仅允许管理器窗口调用」；
- `require_perm(PERM_X)`——皮肤需在 skin.json 声明对应权限（每次调用实时重扫 manifest，改动立即生效）；
- `caller_skin`——免权限基线命令的身份确认（沙箱内操作：自身目录文件/自己 schema 设置/日志/广播）；
- SkinLabel——无害自作用（身份由 label 反查：show_skin_context_menu/skin_set_menu_items/open_skin_devtools/skin_console_log）；
- ControlTarget——control 族：作用于自己免权限（skinId 省略/空串/自己 id = 自己，`resolve_control_target` 一处收敛——皮肤经桥拿不到自己 id），指定他人过 control 门（skin_list_skins 例外恒走 control——它本质就是「看他人」）；
- Ungated 仅 start_skin_drag/start_skin_resize 两条（只作用调用方自身窗口，连身份校验都无必要）；
- 网页皮肤被 tauri remote-origin 守卫整层拦在命令之外。

### 8.2 权限模型（12 种，三档仅展示层）

高危（红）：`shell` / `system` / `file_system`；中危（黄）：`registry` / `clipboard` / `mic` / `control`；低危（蓝）：`media` / `notify` / `sys_info` / `network` / `open_link`。**后端校验仍是「声明/未声明」二元**，三档只是安装引导页/编辑器的展示分级。安装引导页逐条展示并按档标注。**未知名忽略**（旧皮肤残留 `"files"` 声明无害；`files` 这个名字永不许复活——旧声明会静默获得新语义能力，任意路径读写才另起 `file_system` 新名；`media_info` 同理已并入 `media`）。

### 8.3 命令族速览（对外契约见皮肤开发指南 §5）

- **sys_info（低危，13 条只读）**：get_cpu_info/get_gpu_info/get_memory_info/get_disks_info/get_disk_space/get_network_info/get_os_info/get_battery_info/get_monitors/get_system_theme/get_processes/get_idle_time/get_foreground_window_info。速率类读数 = **采样基线模式**（静态 Mutex 持采样器，首调返回 0，皮肤每秒轮询）；sysinfo 0.32 无磁盘 IO（走 PDH `\LogicalDisk(*)\Disk Read/Write Bytes/sec`，按盘符 join，勿用 `\PhysicalDisk`）；GPU 两来源拼装（DXGI 枚举名称/LUID/总量 + PDH 占用）；前台窗口 title 上限 511 字符（SendMessageTimeoutW 300ms 防假死窗口冻结宿主）。
- **media（低危，7 条）**：get_volume/set_volume/set_mute/get_media_info/media_control/media_seek/get_audio_spectrum（系统输出环回频谱；麦克风频谱另归 `mic` 中危）。SMTC 会话选取 = 枚举+择优（正在播放>有进度>有元数据），不读 GetCurrentSession；position_secs 播放中由后端按「快照+速率×时差」推算推进；无会话返回 null 不是错误；三条 SMTC 命令必须 async+spawn_blocking。音量为 COM 约定：`CoInitializeEx(MTA)` 后 **S_OK 与 S_FALSE 都配对 CoUninitialize**（只认 S_OK 漏配一次）；**主线程 COM 套间属于 tao**（任何 CoInitializeEx(MTA) 不得跑主线程——tao 建窗 OleInitialize 要 STA）。
- **registry（中危）**：只读，根键白名单 HKCU/HKLM/HKCR/HKU，六种值类型（qword 超 2^53 丢精度、binary 回 base64）。
- **shell（高危）**：`run_command`——普通权限不提升、CREATE_NO_WINDOW 隐藏窗、120s 超时杀进程、输出截断 1MB、stdout/stderr 双线程分读、GBK 经 OEM 回退转码（截断点回退 UTF-8 字符边界）、exit code 可负。必须 async+spawn_blocking。
- **clipboard（中危）**：读/写文本，走 tauri-plugin-clipboard-manager（Rust 侧 app.clipboard()）。
- **notify（低危）**：`show_notification`——Toast 三件套缺一不可（启动 `SetCurrentProcessExplicitAppUserModelID("Driftlet")` + 开始菜单 Driftlet.lnk 盖 PKEY_AppUserModel_ID 自愈 + `CreateToastNotifierWithId` 同 ID）；标题/正文 64/256 字符截断、XML 五字符转义；AUMID 宽字符缓冲区**故意泄漏**（属性袋惰性回读，释放即 use-after-free）；`create_shortcut` 里 CoInitializeEx 后永不 CoUninitialize（propsys 在 MTA 套间销毁时堆损坏 0xc0000374 实测）。AUMID 同时是任务栏图标解析键（快捷方式须带 SetIconLocation）。
- **file_system（高危，5 条）**：skin_read_any_file/skin_write_any_file/skin_list_any_dir/skin_create_any_dir/skin_delete_any_path——任意绝对路径、整盘可读可写（**四禁写根**：skins_dir/config_dir/update 目录/exe 程序目录——否则皮肤改写自己 skin.json 静默提权，或替换更新目录安装包借「立即安装」升级为代码执行）；UNC 双形态+Prefix 级拒绝（SMB/NTLM 外发面）；变更目标拒 `..`（Windows 沿符号链接逐分量解析 `..` 非纯词法——`ensure_mutable_any_path` 先拒 `..` 分量再 resolve_location 最深现存祖先 canonicalize）；删除目录树须显式 `recursive:true`；错误透传系统原文；文本通道 UTF-8 严格解码。展示型引用走 `__fs__` 端点（§6）。
- **control（中危，8 条）**：skin_list_skins（恒 control）+ skin_get_window_config/skin_set_window_config + 生命周期三条 + 显隐两条（作用于自己全免权限）。窗口配置 patch 按键部分更新、未知键/错类型整批拒绝；opacity/x,y/width,height/position_locked/resizable 要求目标已加载（运行态操作需要窗口），其余键未加载仅持久化；zoom 与 width/height 同批先应用 zoom；单边 x/y、width/height 合并取当前值；**配置修改逐项分发到管理器命令的 `set_skin_*_impl` 进程内实现**（同一条路径，勿在 skin_api 另抄一份）；生命周期三条目标是自己时 fire-and-forget（发起调用的 webview 随即销毁，返回值不可依赖）。
- **network（低危）**：`http_request`——绕 CORS 读任意公网 URL 响应、自定义方法/头（六方法白名单 GET/POST/PUT/PATCH/DELETE/HEAD）、超时默认 15s 钳 1–60s、响应体截 4MB、binary 时 base64 收发、HTTP 4xx/5xx 照返状态码不 reject（仅网络层失败 reject）。**SSRF 防线**：localhost/环回/链路本地/私有/未指定/广播一律拒绝（含 inet_aton 数字字面量形态经 `parse_inet_aton` 还原后同规则——WHATWG 解析已先归一化，本函数是纵深）；**重定向逐跳复检**（`redirects(0)` 手动跟跳、每跳重查 scheme 与私网、上限 3 跳——勿改回 ureq 自动跟随，302 跳板曾整体绕过首发校验，审查 H1）；请求头逐跳 `headers_for_hop` 过滤（跨源剥 authorization/cookie/proxy-authorization，转 GET 丢体时另剥 content-length/content-type——否则皮肤令牌随 302 泄漏第三方，复审 D-A）。
- **open_link（低危）/ system（高危）**：`open_external` 用 `ShellExecuteW`（shell 插件 open 已弃用勿改回）；URI 白名单 http(s)/mailto/ms-settings——http(s) 过 open_link 或 system 任一（`require_any_perm`，拒绝时报首个权限名低危在前），mailto/ms-settings 需 system；本地路径一律拒绝（本地路径面已裁撤）。分层判定 = 纯函数 `open_external_required_perms`（测试钉住）。system 另含电源五条（`power.rs`，刻意无路径/无目标参数）：lock_workstation/monitor_off（PostMessage 广播 SC_MONITORPOWER——勿改 SendMessage）/sleep（SetSuspendState 不强制）/power_control（shutdown/restart/logoff，不带 EWX_FORCE）/empty_recycle_bin（系统确认框，已空直接成功）。
- **免权限基线**：皮肤目录文件沙箱 4 条（skin_read_file/skin_write_file/skin_list_dir/skin_delete_file——读 ≤32MB 写 ≤16MB、路径相对皮肤目录、拒绝对/.. /冒号/符号链接/DOS 设备名（CON 曾挂死主线程）、skin.json/settings.json* 根目录直下禁写禁删、写自动建父目录、文本通道 UTF-8 无 BOM 严格解码）+ 自己 schema 的设置读写（skin_get_setting/skin_set_setting——只认声明过的 key，值过同一 `validate_custom_setting_zh` 校验；写盘后 `emit_to("main", "skin-setting-changed")` 定向同步管理器）+ skin_log/skin_console_log + skin_broadcast（channel 1–64 字节、payload ≤16KB、含自己、卸载中收不到、免权限=无鉴权——channel 名公开、勿信广播内容）。

### 8.4 错误处理约定

命令失败 reject 的是**面向人的可读文案**（绝大多数随管理器界面语言；少数参数校验文案——skin_broadcast/skin_set_menu_items/http_request 等——硬编码英文）；「没有数据」由返回值表达（null 或标志位），动作类失败才 reject；按宿主能力分支读 `__DESK_PP__.hostVersion` 数字段比较，不靠捕获错误探测功能。

### 8.5 稳定性约定（勿回归）

- **全域 Mutex 中毒恢复**：`.lock().unwrap_or_else(|e| e.into_inner())`。
- **持锁守卫不得跨「会再取同一把锁」的调用**（不可重入；锁序见 §4）。
- **FFI 回调必须 `catch_unwind`**（skin_subclass_proc、EnumDisplayMonitors 等——panic 不穿越 FFI 边界；进程句柄泄漏同步修复；WM_GETMINMAXINFO 先默认处理再覆写）。
- **热键簿记一律以 `Shortcut` Display 规范化串为准**（小写修饰词 + keyboard-type 主键）——用户输入、配置存储、注册表键同串比较，否则重复检测失效。
- 逐皮肤显隐热键 = 常驻注册表 + 独立分发（命中优先于全局）：配置存 `skin_settings[id].hotkey`，启动/导入后按 config 全量重建 `SKIN_HOTKEYS`；皮肤未加载时按下静默无效果。

## 9. 皮肤包与安装链路

**.dskin = zip**（skin.json 在根目录或唯一一级子目录）。创作者用 `tools/pack-skin.exe`（免安装、无 Node/Rust 环境）打包：**它与安装端共享同一套 SkinManifest 强类型校验 + 安全上限（256MB/1GB/10000 文件）的手工镜像**（`tools/pack-skin/src/main.rs` ↔ `src-tauri/src/skin/types.rs`、`loader.rs` 校验、`package.rs` 上限）——**改动必须同步并重建 exe 覆盖 `tools/pack-skin.exe`**（exe 入库，供创作者免环境使用；仓库有 check-pack-skin-mirror.py 辅助）。打包排除：`settings.json*`（用户数据）、.git/.svn/node_modules、已有 *.dskin、.DS_Store/Thumbs.db/desktop.ini；缺 version 打印警告不拦截（更新判断退化）；min_host_version 非纯数字点分只提示不拦截；结构错误带行列号拒绝。

**安装端校验与防护**（`skin/package.rs`）：enclosed_name 防 zip-slip；体积按**实际解压字节**计量（io::copy 累加，不信 zip 头声明——zip 炸弹正是「声明很小解压很大」）；安装/更新的暂存目录复制 `copy_dir_recursive` 跳过符号链接与 junction（junction 不被 is_symlink 标记，按 reparse 属性位判）且限深 32 层（MAX_COPY_DEPTH）；实装 id 与确认页解析 id 一致（TOCTOU 收口——「确认 A 的权限、装 B 的内容」不一致即回滚拆除）。

**安装 = staging 回滚四步**（`install_package`）：① 完整复制到 `skins/.staging-<id>`；② 已存在的 `<id>` rename 为 `.<id>.old`；③ staging rename 换入（失败把 .old rename 回去）；④ 从 .old 恢复 settings.json 后删 .old。任一步失败不留半成品。皮肤扫描跳过 `.` 开头目录（staging/.old 不会被列出）。更新正在运行的皮肤：先卸载再安装，装后**保持卸载**（产品决定：更新/重装/回退不自动恢复运行）。文件选择器只过滤 .dskin。

**双击安装（文件关联）**：`tauri.conf.json` 的 bundle.fileAssociations 由 NSIS 写注册表——仅安装版有双击入口（绿色 exe/dev 无，但可命令行参数测试：`npm run tauri dev -- -- "D:\path\x.dskin"`）。**冷/热两条入口路径不能合并**：冷启动 `dskin_arg(std::env::args_os().map(to_string_lossy))`（`args()` 对非 UTF-8 参数直接 panic——release 无控制台即静默闪退；跳过 argv[0]、扩展名大小写不敏感、文件须存在）→ 存 `AppState.pending_package`、主窗立即 show、前端就绪后 `take_pending_package_install` 主动拉取（Mutex::take 消费型只弹一次；**此处不能 emit 事件**——前端 listener 未注册，发了就丢）；热启动 = single-instance 回调（插件第一位）→ `tray::show_manager_window` + emit。已知窗口期：冷启动后前端未就绪的几百毫秒内第二次双击可能丢（显示第一个包的引导页），可接受。**安装串行化 = install_lock**（反复双击并发装同一皮肤时 remove_dir_all 与复制互踩）。安装引导页 `install-wizard.js` 四态 + `_gen` 代际计数作废旧异步结果。.dskin 图标 = `src-tauri/icons/dskin.ico`（icon/dskin-icon.png 缩出 16–256 共 10 帧，tools/make-ico.cjs 打包）。

**NSIS 安装器定制**（`src-tauri/windows/installer.nsi`，取自 tauri-cli v2.11.4 tag 的自维护模板——**升级 @tauri-apps/cli 必须重新同步该模板**）：① 单包双语言 `nsis.languages = ["English", "SimpChinese"]`——运行时按系统 UI 语言自动匹配、无匹配回退首位（English 必须在前）；钩子把 `$LANGUAGE` 写注册表供卸载器 `MUI_UNGETLANGUAGE`（不写会弹语言选择框）。② 完结页「开机自动启动」勾选框（MUI2 原生两槽位 RUN/SHOWREADME 之外的第三个，经页面坐标位自定义）。③ 欢迎页文案换自定义 LangString（原版「请先关闭其他所有应用程序」与本安装器无关）。④ 许可页按安装语言分文件（中文 = installer-license-zh.txt 纯中文、其他 = installer-license-en.txt——**两份都必须 UTF-8 带 BOM**，无 BOM 编译期不报错、运行时按 ANSI 解码中文全乱码；模板内硬接线 `MUI_PAGE_LICENSE` 直指仓库文件，相对路径深度恒定但与 cli 打包布局耦合）；关于页「用户协议 → 查看」与许可页同源同一对文件（`get_user_agreement` 按界面语言取件，commands.rs 有双版同步守卫测试）。⑤ 重装页选项互换（「覆盖安装（保留现有数据）」升为第一项默认；「先卸载再安装（数据将被清除）」降为第二；升级/降级/同版本三分支推荐语全换自定义文案）。⑥ 页脚 BrandingText 改 `${PRODUCTNAME} ${VERSION}`（彼时 stock `${COPYRIGHT}` 因无 copyright 配置恒空、回退 NSIS 默认串；copyright 字段系后补）。⑦ WebView2 运行时地板 `minimumWebview2Version` = 111（容器查询/color-mix 基线——屿族皮肤缩放模型全押其上，过旧运行时声明整体失效、卡件塌陷变色）：已装但过旧时安装器升级（标准版调 EdgeUpdate 在线、**离线版用内嵌离线运行时就地升级**——上游模板只有在线一条路，无网络必败，自定义⑤修复，实机反馈；更新模式同样生效）；运行侧另有启动检查兜底（`webview2.rs`，地板值两侧同值勿单侧改）。

**卸载数据清理 = 钩子 POSTUNINSTALL 全删、无复选框**：应用数据在 exe 旁（便携），模板自己只删安装文件、`$INSTDIR` 只做非递归 RMDir（有残留就失败留下整目录）——钩子在非更新卸载时无条件补删 `RMDir /r /REBOOTOK "$INSTDIR"` 整目录（事故依据：曾只删 config/skins + 非递归重试根目录，update/ 残留安装包让根目录删除失败；口径由此改为「安装目录一律清空」）+ %APPDATA%/%LOCALAPPDATA% 数据 + 注册表。**`${If} $UpdateMode <> 1` 守卫绝不能去**——更新安装先跑旧卸载器，少了它每次更新都会清掉用户配置与皮肤（且更新模式下正在运行的安装包就躺在 update/ 里）。「删除应用数据」复选框已从模板移除（原版无条件创建且无配置开关——只能走自维护模板）。

## 10. 布局备份（导出 / 导入）

设置页一键导出/导入全部配置与皮肤（单个 zip；适合换机与分享布局）。

- **zip 布局**：`driftlet-backup.json` 清单（format/app/app_version/created_at）+ `config/` + `skins/`。
- **导入必须先解压到临时目录、全程校验通过后才动真目录**（体积 5000 条/256MB、条目、zip-slip 防线与皮肤包同一套；必须含 config/config.json，format 只认当前值）。
- **替换前必须卸载全部已加载皮肤**（WebView2 锁目录，Windows 下 rename 必失败）并取 install_lock 与安装互斥。
- **导入崩溃窗口启动回滚**：`.import-old` 存在 = 上次导入中断（成功路径会删掉）——目标目录可能缺失/半成品/完好三态，一律把旧副本挪回去。
- **导入后的运行时重建清单（漏一项就是状态漂移）**：重读 config + prune_stale_entries + 回写内存镜像、语言镜像 + 重建托盘菜单、按 config.autostart 同步 autolaunch 插件、热键全量重建（含逐皮肤）、专注模式态复核、UI 全量重绘。
- **导出侧防线**：目标不得位于 config/ 或 skins/ 内（否则 zip 把正在写入的自己包进去——自包含体积失控；按父目录 canonicalize 判定）；先写临时文件再 rename 就位。
- **选择性导入 = 合并模式**：审查框勾选皮肤后 `import_config(skin_ids)`——每个选中皮肤三段式替换（`.<folder>.old` 让位 → 拷贝就位 → 旧设置值取回），config 并集合并，其余数据不动；导入前审查页展示包内皮肤的权限声明（与安装引导同口径）。

## 11. 更新通道（update.rs）

- **启动检测**（默认开，设置可完全关闭；每进程只查一次）：`check_update` 查公开仓库 GitHub releases API（UA = `Driftlet/<version>`，仅 UA 不带任何用户数据），数字段版本比较；网络失败静默不打扰启动。**发现新版立即弹窗**（不等下载完），下载期间进度条 + 通道指示，完成主钮转「立即安装」，全部通道失败才降级「前往下载」。
- **信任模型（勿回归）**：版本号与官方 SHA-256 **只取自 api.github.com**——哈希解析自 release 说明的 `SHA256: <hex>` 行（发布流程强制）；下载链接钉死在公开仓库 release 下载域前缀校验（只接受 GitHub API assets 返回的链接形态）；加速镜像通道只在发布说明附官方哈希时启用；落盘哈希不符立即作废。
- **多通道竞速 + 分段并行**：GitHub 直连与加速镜像同时开工、谁先完成用谁；单源内 Range 分 8 段并行（国内单连接常限速十几 KB/s，分段约一个量级提速）；首请求 Range 探测段兼用 content-range 探总大小（206 → 预分配 + 偏移写）；进度节流 500ms；超时 60s/10s/15s 分层。
- **免重下**：同版本安装包已下载完成、或上次点了「稍后」，重启后不再重复下载，直接提示「立即安装」（版本标记 + `.part` 分段管理）。
- **安装**：`install_update`（require_manager）启动固定目录里的安装包（只认我们刚下载的那个，不接任意路径）——执行前复核标记完整 + 版本新于当前 + 文件哈希一致，缺一即拒（用户确认的「安装官方更新」不能执行被第三方改写的安装包）；随后 `tray::graceful_exit` 整站退出（NSIS CheckIfAppRunning 接力）。
- **垃圾不堆积三道闸**：固定文件名覆盖 + 分段 `.s<源>.part` 起手全清/失败清 + 启动清理（当前版本 ≥ 标记版本 = 装上了 → 删安装包与标记）。
- **更新目录入 file_system 四禁写根**（审查 H2）。

## 12. 全局功能

### 12.1 托盘（tray.rs）

菜单 = 显示管理器 / 重载全部 / **专注模式勾选** / 皮肤显隐子菜单（每已加载皮肤一行勾选，点选切显隐）/ 布局方案子菜单（点击即应用）/ 退出。「皮肤显隐」子菜单维护分两层：加载集变了才重建整菜单、只显隐翻转仅按真实可见性 set_checked（热键连发不抖菜单）。**全部可见性变化走 `hotkey::sync_tray_toggle_item` 漏斗**（全局热键/托盘勾选/Alt+F4 降级隐藏/编辑器按钮/load/reload 收尾都经它）——同时向管理器发 `skins-visibility-changed`，「已隐藏」徽标按真实窗口状态刷新不靠热键簿记。托盘图标逐尺寸 PNG（§7.10）。

### 12.2 热键（hotkey.rs）

- **全局热键 = 专注模式开关**（默认 Ctrl+Shift+Alt+D，专注模式面板中修改或禁用；1.2.4 由「一键显隐全部皮肤」升级而来——默认动作档「隐藏」时与旧行为一致，白名单皮肤不再被波及）。注册失败（被占用）存 `hotkey_error`，前端 init 拉一次 toast（不静默）。
- **逐皮肤显隐热键**：编辑器为每皮肤配一个组合键（与全局热键/其他皮肤重复或系统占用拒绝保存）；常驻注册表独立分发，命中优先于全局；簿记一律 Shortcut Display 规范化串。

### 12.3 专注模式（focus.rs）

一键（热键/托盘/面板）或全屏自动进入「免打扰桌面」——按动作档关闭所有非白名单皮肤，退出按进入时快照还原：

- **动作档**：隐藏（默认，秒回状态不丢）/ 卸载（回收全部内存，恢复需重新加载）；模式期间改档不影响本次还原（按进入档还原）。
- **白名单**：面板内按皮肤勾选豁免，两种动作档都不碰。
- **全屏自动进入**（默认关）：2.5s 轮询检测全屏应用（游戏/全屏视频，含独家全屏；容差 ≤4px），全屏结束 5 秒防抖后自动退出；全屏期间手动退出则本次全屏周期不再自动进入。
- **崩溃安全**：模式态 + 进入档 + 快照持久化在 `config.focus_mode`——模式激活期间应用退出/崩溃，下次启动按快照恢复，不丢加载集。
- 入口状态呈现：导航栏「专注模式」项激活时常亮信标。方案定案：`docs/proposals/专注模式方案-2026-09.md`（仅开发仓库）。

### 12.4 日志（app_log.rs + log 窗）

后端缓冲常驻（`VecDeque<LogEntry>` 环缓 1000 条淘汰最旧、单条截 1000 字符、每条带单调 seq），前端按需拉取。捕获口径 = 自定义 log crate logger（只认 `driftlet_lib` target——wry/tao 等第三方噪音不进）+ 皮肤侧 console hook 转发（洪防参数见 §6）+ 显式 `skin_log`（level 只认 warn/error 其余归 info）。操作流水挂点（Info 级仅 stderr 不到窗口）：管理器启动/关窗销毁与无托盘退出/退出/热键触发（**不要放进 `focus::toggle`**——托盘菜单切换走同一函数会被误记）/皮肤加载卸载（impl 汇聚点）/设置修改（两侧各一条，**只记 key 不记 value**——password 值连 stderr 也不该出现）。日志窗口：设置页「高级」`open_log_window`（require_manager，防叠开）创建——**必须是 async + spawn_blocking 建窗**（同步命令在主线程 WebView2 IPC 回调上下文就地 build 会卡死主线程，实测复现）；主题/语言烘焙进 URL query（日志窗过不了 get_app_config 的 require_manager）；前端**先 listen 再 invoke get_app_log**（顺序反了丢窗口期条目），按 seq 去重转增量；`get_app_log`/`clear_app_log` 由 `require_log_window` 按 label 把关（缓冲含内部路径与其他皮肤消息，不能放给皮肤读）。

### 12.5 开发模式：皮肤热重载（hotreload.rs）

**仅 debug 构建**（setup 里 `cfg!(debug_assertions)` 门控）+ 设置页开关（`config.hot_reload`，默认关）。单 notify watcher 递归监视整个 skins 目录，按皮肤文件夹防抖 300ms 复用 `reload_skin_impl`；**自身写入过滤是命门**：settings.json（及 .tmp/.bak）、preview.png、.staging-*/*.old 一律不触发，否则死循环——**新增任何应用自身往皮肤目录的写入都必须登记进过滤表**。重载必须 spawn（旧窗口 label 要等事件循环处理 close 才释放，同线程同步 destroy+create 撞 "already exists"）。

### 12.6 提权提醒（elevation.rs）

程序不需要管理员（清单 asInvoker；全部能力标准用户可用）。`run()` 最前（Builder/single-instance 之前）查 `TokenElevation`（不是「用户是不是管理员」——UAC 下管理员普通启动不触发）；提权则只**提醒一次**（MessageBoxW，此刻窗口系统未建立；语言 early 预读 config）说明影响（shell 权限皮肤静默管理员执行、Explorer 拖 .dskin 被 UIPI 拦截），「是」= `allow_elevated` 持久放行，「否」= 退出。**不做任何降级尝试**——两条路线实测废弃勿改回：① 任务计划代起（触发杀软行为检测 Behavior:Win32/Execution.A!ml，且对真 Administrator 原理无效）；② SAFER 受限令牌 + CreateProcessWithTokenW/AsUserW（UAC 提权的标准用户令牌里根本没有所需管理员特权，实测双臂全挂）。1.1.2 时代的历史残留任务与 `--demote-cleanup` 参数已随降级机械一并移除。`DRIFTLET_ALLOW_ELEVATED=1` 与 `allow_elevated` 字段都是跳过提醒的 opt-out。`elevation::enable_privilege` 是共享提权助手（AdjustTokenPrivileges 返回 Ok 仍须查 GetLastError ≠ ERROR_NOT_ALL_ASSIGNED）——skin_api 的 sleep/power_control 经它提 SE_SHUTDOWN_NAME，勿抄第三份实现。

### 12.7 管理器「关窗即销毁」

管理器渲染进程 ~80MB 是皮肤之外最大常驻块；挂起路线（TrySuspend）实机证伪（见 docs/已知问题.md，仅开发仓库）。关窗（关闭按钮/Alt+F4，前端 `win.close()` 统一走 CloseRequested 分支）= `prevent_close` + `destroy()`；唤回即重建（托盘/右键「打开皮肤配置」/双击 .dskin——后两者在管理器已销毁时先重建再进入对应页面，`pending_open_config`/`pending_package` 暂存拉取模式）。启动自动更新检测每进程只查一次（重建不重弹）。

## 14. 仓库纪律（AGENTS.md 硬性约定）

1. **文档双版同步**：三对必须成对更新——`docs/皮肤开发指南.md` ↔ `skin-development-guide.md`、`docs/关键机制.md` ↔ `critical-mechanisms.md`、本文档 ↔ `architecture-and-mechanisms.md`；CHANGELOG.md 仅中文版。
2. **pack-skin 镜像同步**：types.rs/loader.rs/package.rs 的镜像在 tools/pack-skin/src/main.rs——改动必须同步并重建 exe 覆盖入库。
3. **版本号四处一致**（见 §1）。
4. **命令闸门**：skin_api 新增敏感命令必须过 require_perm；管理器命令必须首行 require_manager；日志缓冲读取必须过 require_log_window；**任何新命令必须在 policy.rs 的 COMMAND_POLICIES 登记档位**（完备性测试双向核对，漏登记即测试红）。
5. **vendored 补丁**：src-tauri/vendor/ 内的 NOTE(driftlet) 补丁（tauri-runtime-wry / tray-icon）升级依赖时必须保留。
6. **行尾**：.gitattributes 定 `* text=auto eol=lf`（*.ps1 为 CRLF）；git status 出现无内容差异的脏文件先查行尾。
7. **生成物**：dist/、node_modules/、target/ 不入库；`src-tauri/gen/schemas/` 知情入库（编辑器补全 capabilities 用），插件/capabilities 变更后随构建 regenerate 一并提交。
8. **实机测试清单**（见 §13）发布前必过、新增功能必补条目。

**提交规范**：详细中文 conventional（feat:/fix:/refactor:/chore:/docs:），涉及关键机制的变更把事故依据写进提交信息或 docs/关键机制.md。**CHANGELOG 口径**（仅中文版、不进公开仓库；面向 releases 页读者——发布时摘节 + 英文现译）：不写仅开发仓库内容（内部文档引用/工具链名/流程叙述/簿记数字）；技术细节以公开代码与公开文档为准；开发中又拆除、未随任何公开发行版落地的功能不写；周期内对未发布功能的修改/迭代同样不另写（只写最终落地形态）。更新说明要精简——写用户能感知的变化，不写实现细节清单。

## 15. 事故史模式总结 + 关键机制条目对照表

### 15.1 反复出现的事故模式（血泪抽象）

1. **「创建后 eval 恢复状态」必败**——与页面加载赛跑。正解永远是建窗 URL query 原子烘焙（opacity/locked/resizable 同一路径）。
2. **跨线程 Win32 调用静默失败**——SetWindowSubclass 等必须窗口所属线程（run_on_main_thread）；FFI 回调必 catch_unwind。
3. **Tauri 2 非 async 命令跑主线程**——凡阻塞（子进程/COM/建窗/截图）必须 async + spawn_blocking，否则冻结整站。
4. **HWND / 句柄会被系统回收复用**——一切按 HWND 的登记（吸附/穿透）必须随销毁摘除。
5. **「事件只发一侧」造成显示脱节**——凡状态变更，持久化、皮肤侧事件、管理器侧广播三条路要想全（单一汇聚点 + 完备性测试是标准解法）。
6. **Option 跟随 vs 显式选择**——「未设置 = 跟随 manifest」语义的字段下发面板前必须解析有效值；裸 None 直灌前端必然显示脱节。
7. **数字/名称写进文档后会漂移**——命令计数、像素尺寸、函数名一旦被代码演进甩掉就成真错误（本仓库 2026-09 全量文档审查曾一次修 33 处）。改代码时搜一遍文档里的函数名/数值。
8. **安全上限不信声明信实测**——zip 体积按实际解压字节、路径按 canonicalize、重定向逐跳复检。
9. **模板/镜像/双版这类「两处维护」必须配对提交**——pack-skin 镜像、双版文档、NSIS 自维护模板，各有一次性事故教训。
10. **实机比推理可靠**——边缘吸附手感、TrySuspend 挂起、取色吸管、降级路线都是「推理可行、实机证伪」；新机制先过实机测试清单再定案。
