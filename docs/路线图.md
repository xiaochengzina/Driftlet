# 路线图（候选方向）

核心链路（安装包 → 皮肤包 → 设置体系 → 窗口机制）已齐，本文档收录下一步候选方向，按优先级排列。每项含动机、实现要点与成本估计，动工前再单独细化方案。

## 优先级总览

1. 应用自动更新 —— 产品闭环最后一块
2. 皮肤商店 / 远程仓库（静态索引起步）—— 平台分发渠道
3. ~~小项穿插：皮肤热重载、配置导出导入（~~全局快捷键~~ 已实现）~~ 均已实现，见 §3 §4
4. 按需：多显示器支持（~~系统数据源 API~~ 已基本实现，见 §5）
5. 发布前收尾（见末节）

## 1. 应用自动更新

- **现状缺口**：无更新通道，用户每次升级都要手动下载安装包重装，安装/卸载机制做得再完善也留不住人。
- **方案**：`tauri-plugin-updater` + 静态 `latest.json`（版本号 + 下载地址 + 签名），直接挂 GitHub Releases；国内用户可走 Gitee Releases 做第二 endpoint（updater 支持多 endpoint 回退）。
- **要点**：
  - updater 强制签名校验：生成密钥对，公钥写进 `tauri.conf.json`，私钥离线保管（丢私钥 = 更新链断裂，泄露私钥 = 任何人可推伪更新）。
  - 当前 NSIS per-user 安装（`installMode: currentUser`）天然兼容：更新不需要提权，且更新流程走 `$UpdateMode=1` 路径，用户配置与皮肤保留（见 `关键机制.md` 卸载条目，该守卫是自动更新安全的前提，勿回归）。
  - 发布流程需加一步：构建后生成/上传 `latest.json` 与签名文件。
- **成本**：中。

## 2. 皮肤商店 / 远程仓库

- **现状缺口**：皮肤只能靠用户手动获得 `.dskin` 文件，平台没有分发渠道。
- **起步方案（静态索引）**：仓库（或 GitHub/Gitee Pages）放一份静态 `index.json`（皮肤 id、名称、简介、预览图、下载地址、版本号）；管理器加「发现」页浏览、一键下载——下载后复用现有 `.dskin` 安装管线（与双击安装同一条路径，含版本更新保留用户设置）。顺带得到**已装皮肤更新检查**：本地 version 与索引比对，列表页提示可更新。
- **进阶伏笔**：
  - ~~皮肤权限声明~~ **1.0 已实现**：`skin.json` 声明 6 种敏感权限（files / registry / shell / system / clipboard / mic），超范围调用由后端 `require_perm` 拒绝；安装引导页逐条展示权限声明并标注高危项（shell / mic）。剩余缺口是商店侧按权限做审核与展示。
  - 作者入驻、评分、审核 —— 远期，需要真实用户量再议。
- **成本**：中（静态索引版）；大（完整商店）。

## 3. 皮肤开发热重载（已实现）

- **落地**：`hotreload.rs`（`notify` crate 单 watcher 递归监视整个 skins 目录，免 per-skin 增删维护），按皮肤文件夹防抖 300ms 复用 `reload_skin_impl`；仅 debug 构建开启（setup 里 `cfg!(debug_assertions)` 门控，生产无 watcher 开销）；设置页有总开关（默认开，正常用户无需开启）。
- **要点（勿回归）**：自身写入过滤——`settings.json`（及 tmp/bak）、`preview.png`、`.staging-*` / `*.old` 暂存目录不触发重载，否则死循环；新增皮肤目录写入点必须同步扩充过滤清单。

## 4. 布局 / 配置导出导入（已实现）

- **落地**：设置页「备份」行。导出 = `config/` + `skins/`（含各皮肤 `settings.json` 用户值）打成带清单（`driftlet-backup.json`，format=1）的 zip；导入 = 体积/条目/zip-slip 校验 + `config/config.json` 与清单 format 验证 → 卸载全部皮肤 → 暂存替换两个数据目录（`*.import-old` 回滚）→ 重建运行时状态 → 前端整页 reload 再同步。

## 5. 系统数据源 API（~~按需~~ 已基本实现）

- **现状**：桌面挂件最受欢迎的几类数据源已齐备——SMTC 正在播放（`get_media_info` / `media_control`，曲目/封面/播放控制）、电池（`get_battery_info`）、实时网速（`get_network_info` 各适配器带 `upload_bps` / `download_bps`，首次调用为基线 0）、CPU / 内存 / 磁盘 / GPU、音量 / 静音、音频双源频谱、空闲时间 / 前台窗口 / 显示器列表、OS 信息 / 进程列表。用法示例见 `examples/sys-monitor`。
- **天气**：需外部 API + key，明确不做进本体，留给皮肤自行 fetch（CSP 的 `connect-src` 放开与否需核实）。
- 后续新增数据源仍按原约定：每类独立成一个 Tauri command（或带推送的事件流），皮肤经 `__DESK_PP__.invoke` 调用，做之前先在 `皮肤开发指南.md` 补对应接口文档。

## 6. 多显示器支持（按需）

- **动机**：多屏用户希望指定皮肤落在哪块屏、按屏记忆布局；单屏为主则价值有限。
- **要点**：皮肤窗口位置持久化需记录显示器标识（当前只存坐标，换屏/拔屏后坐标失效）；与「贴桌面」机制（父窗口 WorkerW 跨整个虚拟屏）的交互要在 `关键机制.md` 的约束内实机验证。
- **成本**：中。

## 1.0 发布后实机回归清单

以下场景与本轮修复直接相关，发布后在新机器 / 真实环境逐项过一遍（原「发布前收尾」两项均已处理：README 安装包段落已更正为「仅 NSIS、中英双语随系统」，边框缩放待验证条目已从 `已知问题.md` 移除）：

- **多皮肤贴桌面 z 序收敛**：≥2 个皮肤贴桌面，Win+D 两个周期后都不被遮挡、不相互翻转。
- **unpin 后任务栏不可见**：皮肤取消贴桌面后，任务栏与 Alt+Tab 都不出现该皮肤（双 bit 清理）。
- **快捷键占用重试**：全局快捷键被占用注册失败后，在设置里重输同一组合可重试成功。
- **边框缩放最小尺寸**：拖边框缩到最小被钳制在 60×40（按 DPI 缩放），窗口不会小到抓不到。
- **双入口安装权限展示**：「+ 添加皮肤」与双击 `.dskin` 两条入口都在引导页展示皮肤的 permissions 声明，shell / mic 标高危。
