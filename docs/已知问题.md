# 已知问题与后续方向

## 已知限制

- **双击安装的启动窗口期**：冷启动（双击 `.dskin` 唤起程序）后前端尚未就绪的几百毫秒内，若再次双击另一个 `.dskin`，第二次的转发事件可能丢失——最终显示的是第一个包的安装引导页。影响仅是需要再双击一次，暂不值得为此引入事件排队。
- **原生日期控件不随界面语言切换**：`<input type="date">` / `datetime-local` 的分段符（年/月/日）与弹层按钮（今天/清除）由 WebView2 的 UI 语言渲染，跟随系统显示语言，与管理器的中英文切换无关（页面 `lang` 与前端 i18n 都影响不到它）。英文系统的用户所见即英文，行为正确；只有「中文系统 + 英文界面」的组合会看到中文原生控件——按此结论不处理。若日后一定要改，只能启动时按配置设 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--lang=xx`（环境级、需重启生效）。
- **敏感命令鉴权每次全量扫描 skins 目录**：`require_perm` 每次调用都重新扫描并解析 manifest 来核对 `permissions` 声明，未做缓存。敏感命令目前都是低频操作，暂无明显体感；若日后出现高频敏感命令或皮肤数量级上升，落点是 manifest 缓存（按文件 mtime 失效）。
- **windows crate 双版本并存**：tauri / wry 栈已在 windows 0.61，sysinfo 与 wasapi 仍依赖 0.57——同一 crate 两个大版本同时编进二进制，纯体积代价，无行为影响。待上游 sysinfo / wasapi 升级对齐后自然收敛。

## 备查

管理器主窗口仍用 tao 原生无边框，已实测无标题栏/边框异常。若日后出现异常，可套用皮肤窗口的 `install_frameless` 子类方案（见 `docs/关键机制.md` 的「无边框机制」）。

原「贴桌面状态下的边框缩放未完整验证」条目已随架构消解：它基于「皮肤是 WorkerW 子窗口」的旧机制（移动/缩放用父窗口相对坐标，与系统模态缩放循环的屏幕坐标存在换算问题）；现行为纯 z 序贴附，皮肤是普通顶层窗口，移动/缩放全程按屏幕坐标工作，无坐标换算问题，随 1.0 移除。
