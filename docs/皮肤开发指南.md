## 1. 皮肤是什么

一个皮肤 = 一个独立文件夹，里面是一个小型网页（HTML/CSS/JS），由 Driftlet 以透明、无边框的桌面窗口展示。皮肤窗口可以置顶或贴在桌面层，支持拖动、边缘吸附、整体缩放、右键菜单、预览图和自定义设置。

### 1.1 最小结构

```
my-skin/
├── skin.json        # 必需，皮肤元信息 / 窗口配置 / 自定义设置声明
├── index.html       # 必需，入口页面
└── ...              # 图片、css、js 等资源（必须放在皮肤文件夹内）
```

可选文件：

- `preview.png` / `preview.jpg` / `preview.jpeg` — 管理器列表预览图；也可以在管理器配置页用「截取预览」生成。

### 1.2 运行机制（30 秒版）

- 管理器为每个加载的皮肤创建一个 WebView2 窗口（透明、无边框），页面经 `skin://` 自定义协议从皮肤文件夹加载。
- 页面加载**之前**，管理器向 HTML 注入桥接脚本 `window.__DESK_PP__`（当前设置值、拖动接管、右键菜单接管、命令通道）——皮肤脚本运行时桥已就绪，无需等待。
- 皮肤的所有「系统能力」（系统信息、文件读写、通知等）都经 `__DESK_PP__.invoke` 调用后端命令获得；敏感能力需要在 `skin.json` 里声明权限（§2.3）。
- 窗口生命周期（加载、刷新、卸载、位置、尺寸、不透明度、置顶/贴桌面）全部由管理器负责；皮肤只关心页面本身，不创建、不移动、不关闭自己的窗口。

## 2. skin.json 参考

完整示例：

```json
{
  "id": "my-skin",
  "name": "My Skin",
  "version": "1.0.0",
  "author": "You",
  "description": "A simple desktop widget",
  "bilingual": false,
  "entry": "index.html",
  "window": {
    "width": 300,
    "height": 200,
    "transparent": true,
    "always_on_top": false,
    "on_desktop": true,
    "resizable": false,
    "zoom": 1.0,
    "opacity": 1.0
  },
  "permissions": [],
  "settings": []
}
```

`skin.json` 文件本身不得超过 **1 MB**（超出将被拒绝加载）。

### 2.1 顶层字段

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 打包分发必填 | 皮肤唯一 ID，规则见下方说明 |
| `name` | 是 | 皮肤名称，显示在管理器列表与配置页 |
| `name_en` | 否 | 英文皮肤名（`bilingual: true` 时英文界面优先显示，留空回退 `name`），见 §4.5 |
| `entry` | 否 | 入口 HTML 文件名，默认 `index.html`；必须是**单纯的文件名**——不允许含 `..`、`/`、`\`、`:` |
| `author` | 否 | 作者，显示在卡片与配置页 |
| `version` | 否 | 版本号，如 `"1.0.0"`；更新包据此判断升级/降级，强烈建议始终填写 |
| `description` | 否 | 一句话描述 |
| `description_en` | 否 | 英文简介（选取规则同 `name_en`） |
| `bilingual` | 否 | 中英双语声明，默认 `false`；为 `true` 时启用各处 `*_en` 英文文案，见 §4.5 |
| `window` | 否 | 窗口默认值，见 §2.2 |
| `permissions` | 否 | 敏感能力声明（`files` / `registry` / `shell` / `system` / `clipboard` / `mic`），见 §2.3 |
| `settings` | 否 | 自定义设置声明，见第 4 章 |

皮肤的唯一标识（skin id）= `skin.json` 的 **`id` 字段**：

- 规则：小写字母、数字、中划线，以字母或数字开头，≤64 字符（如 `controls-demo`）；**Windows 保留设备名不可用**（`con`、`prn`、`aux`、`nul`、`com1`–`com9`、`lpt1`–`lpt9`，含 `con.txt` 这类带扩展名的基名）。
- 它是用户数据的归属键——**同一个 id 视为同一皮肤**；更新包（同 id、更高版本号）会替换文件并保留用户的设置数据（窗口配置按 id 存在全局 config.json；「皮肤设置」页的用户值在安装文件夹的 `settings.json` 中，更新时自动保留——见 §8.3）。
- 打包成 `.dskin` 分发时**必须**声明；以文件夹形式开发/安装时可省略，系统会按文件夹名派生一个。

### 2.2 window 字段

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `width` / `height` | 数字 | 300 / 200 | 初始尺寸，**逻辑像素**（DPI 缩放由系统换算） |
| `transparent` | 布尔 | true | 透明窗口背景（皮肤开发一般都保持 true） |
| `always_on_top` | 布尔 | false | 初始置顶。与 `on_desktop` 二选一 |
| `on_desktop` | 布尔 | true | 初始贴在桌面层（Win+D 显示桌面时仍可见）。与 `always_on_top` 二选一 |
| `resizable` | 布尔 | false | 初始是否允许拖拽窗口边缘/四角调整大小（最小 60×40，开启时边缘显示黄黑动态条纹提示）。用户可在管理器「窗口」页随时开关；开启前皮肤应按 §3.3 做好自适应布局，否则窗口变小内容会被裁剪；边缘 6px 为缩放热区，不再触发 `.drag-region` 拖动 |
| `zoom` | 数字 | 1.0 | 缩放比例默认值（0.5 – 2.0）：实际窗口 = `width × zoom` × `height × zoom`，内容经 WebView2 ZoomFactor 同倍缩放——**皮肤按基础尺寸布局即可，平台完成整体缩放，无需任何适配**。用户可在管理器「窗口」页随时调整 |
| `opacity` | 数字 | 1.0 | 初始不透明度，0.1 – 1.0 |

除 `transparent` 由作者固定外，以上都是**初始默认值**——用户后续在管理器里的修改会覆盖它们并持久化。

### 2.3 权限声明（permissions）

皮肤调用「敏感能力」类后端命令（§5.3）前，必须在 `skin.json` 顶层声明对应权限，否则调用被拒绝：

```json
"permissions": ["files", "shell"]
```

| 权限 | 解锁的命令 |
|------|-----------|
| `files` | `skin_read_file` / `skin_write_file` / `skin_list_dir` / `skin_delete_file`（仅限皮肤自身目录） |
| `registry` | `read_registry_value`（只读） |
| `shell` | `run_command`（普通权限、隐藏窗口） |
| `system` | `set_volume` / `set_mute` / `media_control` / `open_external` / `show_notification`（改变系统状态、打开外部链接/文件、发系统通知） |
| `clipboard` | `read_clipboard_text` / `write_clipboard_text`（读取可能包含用户刚复制的敏感内容） |
| `mic` | `get_mic_spectrum`（麦克风输入——与系统环回不同，这是真实的拾音，涉及隐私） |

规则：

- **只声明实际用到的权限**；未知名一律忽略。
- 只读的系统信息命令（§5.2）与设置读写命令（§5.4）不需要任何声明。
- **权限声明对用户可见**：安装/更新皮肤时，安装引导页会逐条列出皮肤声明的权限，`shell` 与 `mic` 会被标注为「高危」。声明了用不到的权限会降低用户的安装意愿。
- 用户视角：声明了 `shell` 的皮肤等同于可以运行本机程序——发布页请如实说明皮肤用到了哪些权限以及用途。

## 3. 页面开发约定

### 3.1 必须遵守

- **资源一律放在皮肤文件夹内**，用相对路径引用（`<img src="bg.png">`）。皮肤经 `skin://` 自定义协议加载，无法访问文件夹外的路径；引用也可写绝对形式 `http://skin.localhost/<皮肤 id>/<路径>`——Windows 上 WebView2 不支持非标准协议的子资源加载，运行时会把 `skin://localhost/...` 改写为该形式（直接写 `skin://` 引用子资源会报 `ERR_UNKNOWN_URL_SCHEME`）。**推荐始终写相对路径**——绝对形式把皮肤 id 硬编码进代码，文件夹改名即 404。
- 需要透明效果时，把 `body { background: transparent }`，背景画在自己的容器上。
- **布局必须自适应窗口尺寸**：任何元素不得超出窗口可视区——窗口调小时内容随之缩放/重排，不允许溢出被裁剪，也不允许出现窗口级滚动条。具体做法见 §3.3。
- **不要使用 `-webkit-app-region: drag`**。可拖动区域改用 `.drag-region` 类（见 §3.2）。
- 页面任意处的右键默认由应用接管（弹「打开配置 / 刷新 / 卸载」原生菜单，WebView2 默认菜单被禁用）。皮肤如需在某个元素上自己处理右键（如卡片右键编辑）：监听 `contextmenu` 并 `preventDefault()` 即可——桥在 window 冒泡末端检查 `defaultPrevented`，皮肤消费过的右键不弹宿主菜单。（1.0.1 及更早版本无此约定，需 window 捕获阶段 + `stopPropagation()` 兜底。）
- **动态内容优先用 `textContent` 赋值**，不要把用户输入/任务文本等未转义字符串拼进 `innerHTML`（原因见 §6.3）。

### 3.2 可拖动区域

给元素加 `.drag-region` 类，用户按住左键即可拖动窗口：

```html
<div class="drag-region">
  <!-- 这里的空白区域可以拖动窗口 -->
</div>
```

约定：把整个外壳设为 drag-region，交互元素嵌在里面不受影响——按下点落在 `button` / `input` / `select` / `textarea` / `a` / `label` / `[contenteditable]` 上时拖动会自动跳过。其他需要独占 `pointerdown` 的元素（如列表拖动排序），在该元素上 `e.stopPropagation()` 阻断冒泡即可。

注意：开启拖拽缩放（`resizable`）后，窗口最外缘 6px 是缩放热区、优先于拖动，贴边元素按下去会触发缩放而不是移动（§2.2）。

补充：用户可以在管理器「窗口」页开启「边缘吸附」——拖动窗口靠近屏幕边缘或其他皮肤窗口边缘时自动对齐（屏幕边缘优先，吸附间距可自定义；吸附后松手再拖，1 秒内可自由移开且不会移出屏幕）。吸附由应用层完成，皮肤无需任何适配。

### 3.3 尺寸、DPI 与自适应布局

- 窗口尺寸、位置在配置中一律是**逻辑像素**；皮肤内的 CSS 像素与之一致，无需关心 DPI 换算。
- **布局必须适配任意窗口尺寸**——用户可以在管理器「窗口」页随时改宽高、开启 `resizable` 自由拖拽边框、或用「缩放比例」把皮肤整体缩放到 50%–200%（平台经 WebView2 ZoomFactor 完成，皮肤按基础尺寸布局即可，无需专门适配）；皮肤不得依赖 `skin.json` 的默认尺寸。规则：
  - 外壳铺满窗口：`html, body { height: 100% }`，根容器 `width/height: 100%`；
  - 任何元素不得写死超出 `window.width × window.height` 的固定尺寸；
  - `body { overflow: hidden }`，不允许出现窗口级滚动条；
  - 内容超高时不许撑出 body——要么缩放，要么收进自己的容器内部滚动（见下）。
- 两种合规范式（按内容性质二选一）：
  1. **缩放自适应**（时钟、图形类）：字号/间距用 `clamp(下限, min(Xvw, Yvh), 上限)`——`min(Xvw, Yvh)` 保证宽、高任一方向缩小时内容都等比收缩，默认窗口下取值 = 原设计值。
  2. **填充 + 内部滚动**（面板、列表类）：面板 `height: 100%; overflow: hidden auto`，内容超高时在面板内滚动，不撑出窗口。范本：`examples/controls-demo`。
- 固定区块较多时可用媒体查询兜底：矮窗口隐藏装饰性元素，保住核心功能的完整。
- 自检：在管理器里把窗口调小一半再放大一倍，内容应完整缩放/重排——无裁剪、无溢出、无窗口级滚动条。

### 3.4 网络与安全

- 皮肤窗口是完整浏览器（WebView2）：`<img>`、`<script src>`、`fetch`、`WebSocket` 都可以访问外部网络，管理器不做限制。
- 页面的源是 `http://skin.localhost`（`skin://` 协议在 Windows 的改写形态）。`fetch`/`XHR` 请求外部站点属于跨域，**目标服务器需返回 CORS 允许头**；`<img>`/`<script>` 标签式加载和 WebSocket 不受 CORS 限制。
- 皮肤页面没有 CSP 约束——自由，但也意味着没有这层保护：只加载你自己信任的资源和脚本。
- 所有皮肤共享同一个源（`http://skin.localhost`），同源策略**不隔离**皮肤之间对普通资源文件的访问。不要把私密数据存成皮肤文件夹里的普通文件——用户私密数据应该用 `password` 类型的设置项（§4.3），平台保证它不会出现在任何页面里。
- 皮肤包里的代码是**能联网的本机代码**。建议在发布页提醒用户：安装第三方皮肤等同于安装一个桌面小应用。

## 4. 自定义设置（settings）

在 `skin.json` 里声明 `settings` 数组，管理器的「皮肤设置」页就会按声明自动生成控件；值持久化保存，皮肤运行时实时可读。

```json
"settings": [
  { "key": "title", "type": "text", "label": "标题", "group": "文本",
    "description": "显示在顶部的标题", "default": "Hello" },
  { "key": "accent_color", "type": "palette", "label": "主题色", "group": "外观",
    "default": "#ff3333" }
]
```

### 4.1 设置项通用字段

| 字段 | 必填 | 说明 |
|------|------|------|
| `key` | 是 | 唯一标识（皮肤内唯一，是持久化的键） |
| `type` | 是 | 控件类型，见 §4.2 |
| `label` | 否 | 控件标题，缺省显示 `key` |
| `label_en` | 否 | 英文控件标题（双语皮肤专用，见 §4.5） |
| `description` | 否 | 控件下方的说明文字 |
| `description_en` | 否 | 英文说明文字（双语皮肤专用） |
| `group` | 否 | 分组名；同组控件归为一张卡片，组按首次出现顺序排列，未指定的进无标题卡片 |
| `group_en` | 否 | 英文分组名（双语皮肤专用） |
| `default` | 否 | 默认值；缺省按类型兜底（false / 0 / "" / 第一项） |

### 4.2 控件类型一览（19 种）

| type | 控件 | 值格式 | 专属字段 / 说明 |
|------|------|--------|------------------|
| `text` | 短文本输入 | `"字符串"` | ≤256 字符 |
| `longtext` | 长文本输入 | `"字符串"` | 多行，≤4000 字符 |
| `number` | 数字输入 | `数字` | `min` / `max` / `step` |
| `slider` | 滑动条 | `数字` | `min` / `max` / `step`，缺省 0/100/1 |
| `boolean` | 单选开关 | `true / false` | |
| `select` | 下拉选择 | `"a"` | 需 `options` |
| `radio` | 互斥开关组 | `"a"` | 需 `options`，组内只选一个 |
| `multiselect` | 多选开关组 | `["a","b"]` | 需 `options`，值为子集 |
| `weekdays` | 星期选择 | `["mon","wed"]` | 固定周一至周日多选 |
| `time` | 时间选择（24h） | `"HH:MM"` 或 `"HH:MM:SS"` | 精确到秒 |
| `date` | 日期选择 | `"YYYY-MM-DD"` | |
| `datetime` | 日期时间选择 | `"YYYY-MM-DD HH:MM:SS"` | 精确到秒，空串 = 未设；倒计时目标类场景 |
| `password` | 密码输入 | `"字符串"` | 掩码显示（带显隐切换），≤256 字符，适合 API Key。**值不会注入页面**，读取方式见 §4.3 |
| `timerange` | 时间范围 | `{ "start": "YYYY-MM-DD HH:MM:SS", "end": "..." }` | 精确到秒，空串 = 未设 |
| `palette` | 调色板 | `"#rrggbb"` 或 `"#rrggbbaa"` | 预设色 + 自定义取色（取色面板自带屏幕吸管）+ 透明度滑块；`options` 可自定义预设色 |
| `font` | 字体选择 | `"Microsoft YaHei UI"` | 枚举系统已安装字体，空串 = 默认 |
| `tasklist` | 任务列表 | `["条目1","条目2"]` | 用户自由增删改 |
| `todolist` | 待办任务列表 | `[{ "text": "...", "done": true }]` | 带勾选框的任务行；上限 500 条、单条 200 字符（超出静默截断） |
| `datetasklist` | 日期任务列表 | `[{ "time": "YYYY-MM-DD HH:MM:SS", "text": "..." }]` | 每条带日期时间，time 可空 |

`options` 结构：`[{ "value": "a", "label": "显示名" }]`，`label` 可省略（回退显示 `value`）；双语皮肤可再加 `label_en`（见 §4.5）。

### 4.3 在皮肤里读取设置

初始值在页面加载前已注入 `window.__DESK_PP__.settings`（一个 key → value 对象）：

```js
const settings = window.__DESK_PP__?.settings || {};
document.body.style.color = settings.accent_color || '#ff3333';
```

用户在管理器里修改设置后，会实时派发 `desk-setting-changed` 事件（无需重载皮肤）：

```js
document.addEventListener('desk-setting-changed', (e) => {
  const { key, value } = e.detail;
  // __DESK_PP__.settings[key] 已同步为新值，直接重新应用即可
  applySettings();
});
```

**`password` 类型特例（重要）**：所有皮肤共享同一个页面源，`__DESK_PP__.settings` 烘焙进 HTML 的值理论上可被其他皮肤读取（§6.1）。因此 **`settings` 对象里 password 类型的键恒为空串**，真实值只能经 `skin_get_setting` 命令按窗口身份单独获取（§5.4）：

```js
let apiKey = '';
// 启动时读取一次
if (window.__DESK_PP__?.invoke) {
  apiKey = await window.__DESK_PP__.invoke('skin_get_setting', { key: 'api_key' }) || '';
}
// 用户在管理器修改后，desk-setting-changed 事件照常携带新值（该事件只发给本皮肤窗口）
document.addEventListener('desk-setting-changed', (e) => {
  if (e.detail.key === 'api_key') apiKey = e.detail.value;
});
```

规范建议：

- 启动时读一次 `settings` 应用；再监听事件做增量更新。不监听也能在下次重载时拿到新值，但体验差。
- 对取值做防御（`??` 默认值）：新增设置项的旧配置里可能没有值。
- 值的类型与你声明的 `type` 始终一致（后端会校验并拒绝不合法的值），但**改了类型后旧的持久化值会被丢弃回退默认**。

### 4.4 在皮肤里写设置（skin_set_setting）

皮肤也可以主动写自己的设置值——与管理器「皮肤设置」页读写的是**同一个文件**（皮肤文件夹的 `settings.json`），适合做任务清单、倒计时目标这类「皮肤和管理器都能编辑」的数据：

```js
await window.__DESK_PP__.invoke('skin_set_setting', {
  key: 'tasks',
  value: [{ text: '写周报', done: false }, { text: '给绿植浇水', done: true }],
});
```

契约：

- 只能写**自己 skin.json `settings` 里声明过的 key**；未声明的 key 会被拒绝（防止把设置文件当任意存储用）。
- 值按声明的 `type` 走与管理器完全相同的校验与归一化（超长截断、非法值报错）。
- 无需声明 `permissions`：调用方身份取自窗口本身，皮肤无法伪装成别的皮肤，也碰不到其他皮肤的设置文件。
- 写成功后：管理器配置页若正打开会原地刷新对应控件；`__DESK_PP__.settings[key]` 会静默同步为新值，但**不会**向你自己回派 `desk-setting-changed`（你自己刚写的值，回派事件容易成环）。管理器侧的修改照旧经 `desk-setting-changed` 推给你。
- 与管理器同时编辑同一 key 时后写覆盖先写（单值粒度）；不同 key 互不干扰。

### 4.5 中英双语（bilingual）

管理器界面支持中英文切换，但设置 schema 里的文案（分组名、控件标题、说明、选项显示名）由皮肤作者提供，管理器不做机翻。想让设置页跟随管理器语言切换，在 `skin.json` 顶层声明：

```json
{
  "bilingual": true,
  "name": "我的皮肤",
  "name_en": "My Skin",
  "settings": [
    { "key": "title", "type": "text",
      "label": "标题", "label_en": "Title",
      "group": "文本", "group_en": "Text",
      "description": "显示在顶部的标题", "description_en": "Title shown at the top",
      "default": "Hello" }
  ]
}
```

规则：

- `bilingual` 是**作者声明**（告诉管理器「本皮肤提供英文文案」），不是用户选项；缺省 `false`，此时所有 `*_en` 字段一律忽略。
- 管理器语言为**英文**且 `bilingual: true` 时，优先显示 `name_en` / `description_en` 与设置项的 `label_en` / `description_en` / `group_en` / 选项的 `label_en`；**某个字段留空则该处回退显示默认文案**——可以只翻译一部分。
- 管理器语言为中文时始终显示默认文案（`name` / `description` / `label` / `group` / 选项 `label`）。
- 支持双语的字段：顶层的皮肤名与简介（`name_en` / `description_en`），以及设置 schema 里的四类（控件标题、控件描述、分组名、选项显示名）；`default` 等**值**不参与双语（值是数据，会原样传给皮肤）。
- 同一张分组卡片按当前语言的显示文案归并：同组的中文 `group` 若配了 `group_en`，请给组内**所有**控件都配上，否则英文界面下会拆成两张卡片。
- 要不要双语由你决定：不做双语就不写 `bilingual` 和任何 `*_en` 字段，皮肤在任何语言下都显示默认文案。

注意：`bilingual` 与 `*_en` 字段只决定**管理器配置面板**的文案语言——皮肤**页面自身**的界面语言管理器不代管。要让页面跟随管理器语言：初始读取 `__DESK_PP__.language`（页面加载前已烘焙，无竞态），并监听 `desk-language-changed` 事件重新渲染：

```js
function currentLang() {
  return window.__DESK_PP__?.language === 'en' ? 'en' : 'zh-CN';
}
function render() { /* 按 currentLang() 渲染界面文案 */ }
render();
document.addEventListener('desk-language-changed', () => {
  render();  // __DESK_PP__.language 已同步为新值（同 e.detail.language）
});
```

不监听事件也无妨——下次 reload 时桥会烘焙新语言。完整参考实现见 `examples/controls-demo`（§10）。

## 5. 桥接 API（window.__DESK_PP__）

页面加载前由应用注入，皮肤脚本运行时即可直接使用。

### 5.1 桥成员

| 成员 | 类型 | 说明 |
|------|------|------|
| `settings` | object | 当前生效的设置值（key → value）；`password` 类型的键恒为空串，见 §4.3 |
| `invoke(cmd, args?)` | function | 调用后端命令，返回 Promise（失败 reject，值为可读错误文案） |
| `language` | string | 管理器界面语言（`"zh-CN"` / `"en"`）；管理器切换语言时实时更新，并派发 `desk-language-changed` 事件（`e.detail.language`），用法见 §4.5 |
| `positionLocked` | boolean | 位置锁定状态（桥内部使用，只读参考） |
| `resizable` | boolean | 边框缩放开关状态（桥内部使用，只读参考） |
| `setOpacity(v)` / `setResizable(on)` | function | 桥内部使用，皮肤不要直接调用 |

**防御写法**：在纯浏览器里调试页面时桥不存在（§7.2），所有 `__DESK_PP__` 访问都建议带可选链：

```js
const settings = window.__DESK_PP__?.settings || {};
const cpu = window.__DESK_PP__?.invoke ? await window.__DESK_PP__.invoke('get_cpu_info') : null;
```

皮肤可调用的公开命令分三组：§5.2 系统信息（只读，免权限）、§5.3 敏感能力（需声明 `permissions`）、§5.4 设置读写。其余命令一律调不到（§5.5）。

### 5.2 系统信息（只读，无需声明权限）

**速率类读数（CPU/GPU 使用率、磁盘/网络速度）= 两次采样之间的差值，首次调用返回 0（基线）**——建议每秒轮询一次，不要只调一次。

#### `get_cpu_info`

```js
const [cpu] = await window.__DESK_PP__.invoke('get_cpu_info');
// {
//   name: "Intel(R) Core(TM) i7-12700",
//   physical_cores: 12,        // 物理核心数
//   logical_cores: 20,         // 逻辑线程数
//   frequency_mhz: 4800,       // 当前频率（MHz，任务管理器「速度」同款，turbo 时可超基准频率）
//   usage: 23.5,               // 总使用率 %
//   usage_per_core: [10.1, ...] // 每线程使用率 %
// }
```

返回数组（为多路 CPU 预留；普通机器恒为 1 项）。

#### `get_gpu_info`

```js
const gpus = await window.__DESK_PP__.invoke('get_gpu_info');
// [{
//   name: "NVIDIA GeForce RTX 3060",
//   gpu_type: "discrete",          // 显卡类型：discrete（独显）| integrated（核显）
//   usage: 12.0,               // 使用率 %（各引擎求和，上限 100）
//   vram_total: 12884901888,   // 显存总量（字节）：独显 = 专用显存，核显 = 共享系统内存
//   vram_used: 4294967296,
//   vram_usage_pct: 33.3
// }]
```

多 GPU 返回多项；核显（统一内存）的显存总量/占用按共享系统内存计——「专用 + 共享」合计可能超出物理内存，不作口径。

#### `get_memory_info`

```js
const mem = await window.__DESK_PP__.invoke('get_memory_info');
// {
//   ram:    { total, used, free, usage_pct, free_pct },  // 物理内存
//   swap:   { total, used, free, usage_pct, free_pct },  // 页面文件（分页池）
//   commit: { total, used, free, usage_pct, free_pct }   // 虚拟内存（已提交）
// }
// 容量单位均为字节，百分比 0–100；commit 仅 Windows 提供（其他平台为 null）
```

虚拟内存占用看 `commit`：任务管理器「已提交 xx/yy GB」，used = 已提交，total = 提交限制（物理内存 + 页面文件 − 系统保留）。`swap` 只是溢出落到页面文件的部分，内存充足时常恒 0。

#### `get_disks_info`

```js
const disks = await window.__DESK_PP__.invoke('get_disks_info');
// [{
//   name: "系统", mount_point: "C:\\", fs: "NTFS",
//   total: 512110190592, used: 256060604416, free: 256049586176,
//   usage_pct: 50.0,
//   read_bps: 1048576, write_bps: 0   // 当前读/写速度（字节/秒）
// }]
```

每个挂载点一项；速度只对盘符挂载点（`C:` 等）提供，其他挂载方式为 0。

#### `get_disk_space`

指定盘符或路径的空间（取该路径所在的卷）：

```js
const c = await window.__DESK_PP__.invoke('get_disk_space', { path: 'C:' });
// { total, used, free, usage_pct, free_pct }  // 字节 + 百分比
// path 也可以是 "D:\\data" 这类路径；找不到对应卷时 reject
```

#### `get_network_info`

```js
const net = await window.__DESK_PP__.invoke('get_network_info');
// {
//   adapters: [{
//     name: "以太网",
//     ips: ["192.168.1.10"],   // 该网卡的 IP（不含回环与 IPv6 链路本地地址）
//     mac: "AA:BB:CC:DD:EE:FF",
//     upload_bps: 10240, download_bps: 204800  // 字节/秒（首次为 0）
//   }],
//   local_ips: ["192.168.1.10", ...]      // 本机全部 IP（去重，同上口径）
// }
```

#### `get_audio_spectrum`

系统正在播放的声音的实时频谱（WASAPI 环回捕获，不需要麦克风）。首次调用自动启动捕获线程，停止轮询约 30 秒后自动释放音频设备，再次轮询时重新启动：

```js
const { bands, peak } = await window.__DESK_PP__.invoke('get_audio_spectrum', { bands: 32 });
// bands: [0.12, 0.85, ...]  // 各频段能量 0–1，30Hz–16kHz 对数分布；bands 参数缺省 32，钳制到 1–64
// peak: 0.42                // 瞬时峰值音量 0–1
```

无音频设备或捕获失败时 reject（恢复后自动好转）。做拾音条建议用 30–50ms 定时器或 `requestAnimationFrame` 轮询。

#### `get_os_info`

```js
const os = await window.__DESK_PP__.invoke('get_os_info');
// {
//   os_name: "Windows 11 Pro", os_version: "11 (22631)", build: 22631,
//   is_windows_11: true, host_name: "DESKTOP-ABC", user_name: "you",
//   uptime_secs: 86400
// }
```

`os_name` 是产品名（注册表 ProductName）；`os_version` 是 `"{主版本} ({build})"` 格式。

#### `get_processes`

```js
const top = await window.__DESK_PP__.invoke('get_processes', { sort: 'cpu', limit: 10 });
// {
//   total: 217,                          // 进程总数
//   processes: [{ pid: 1234, name: "chrome.exe", cpu: 12.3, memory_bytes: 524288000 }]
// }
```

`sort`：`"cpu"`（默认）/ `"memory"`（其他值按 `"cpu"` 处理）；`limit` 默认 10，钳制到 1–100。`cpu` 是整机占比 0–100（全部核吃满 = 100，任务管理器同口径），**首次调用为 0（基线）**。

#### `get_volume`

```js
const v = await window.__DESK_PP__.invoke('get_volume');
// { volume_pct: 100.0, muted: false }   // 系统主音量与静音状态
```

#### `get_media_info`

当前正在播放的媒体（SMTC——网易云、QQ 音乐、Spotify、浏览器视频等大多数播放器都接入）。**没有播放会话时返回 `null`（不是错误）**：

```js
const m = await window.__DESK_PP__.invoke('get_media_info');
// null，或：
// {
//   title: "歌名", artist: "歌手", album: "专辑",
//   status: "playing",                  // playing | paused | stopped
//   position_secs: 42.5, duration_secs: 231.0,
//   cover_base64: "<图片 base64>",      // 封面；来源应用不提供时为 null
//   cover_mime: "image/jpeg"            // 封面格式（按内容嗅探）；认不出为 null
// }
```

播放器没上报的字段为空串；进度同理可能为 0。`position_secs` 是播放器上报的快照值，播放中不会自行推进（各播放器上报节奏不同，需要平滑进度条请自行插值）。

#### `get_battery_info`

```js
const b = await window.__DESK_PP__.invoke('get_battery_info');
// {
//   has_battery: true,      // 台式机为 false，其余字段此时无意义
//   ac_online: true,        // 电源已接通
//   charging: false,
//   percent: 85,            // 未知时为 null
//   secs_remaining: 7200    // 未知（充电中常如此）为 null
// }
```

#### `get_idle_time`

距用户上次键鼠输入的毫秒数：

```js
const idleMs = await window.__DESK_PP__.invoke('get_idle_time'); // 45230 = 45.2 秒无操作
```

#### `get_foreground_window_info`

当前前台窗口（用户正在用啥）；极少数情况没有前台窗口时返回 `null`：

```js
const w = await window.__DESK_PP__.invoke('get_foreground_window_info');
// { title: "文档 - Word", pid: 12345, process_name: "WINWORD.EXE" }
```

`title` 最长 512 字符（超出截断）；`process_name` 取不到时为空串（如权限不足的保护进程）。

#### `get_monitors`

```js
const ms = await window.__DESK_PP__.invoke('get_monitors');
// [{
//   name: "\\\\.\\DISPLAY1",
//   rect:      { x: 0, y: 0, width: 1920, height: 1080 },  // 物理像素
//   work_area: { x: 0, y: 0, width: 1920, height: 1040 },  // 不含任务栏
//   is_primary: true,
//   scale_factor: 1.25        // DPI 缩放（1.25 = 125%）
// }]
```

注意 rect/work_area 是**物理像素**，与窗口配置用的逻辑像素差一个 scale_factor。副屏的 `rect.x/y` 可为负（主屏左/上方是虚拟坐标负区）。

### 5.3 敏感能力（需在 skin.json 声明 permissions）

声明方式见 §2.3。未声明时调用 reject，错误形如 `皮肤 'my-skin' 未声明权限 'files'`。

#### 文件读写（权限 `files`）——仅限皮肤自身目录

```js
// 写文本（子目录自动创建）
await window.__DESK_PP__.invoke('skin_write_file', { path: 'data/cache.json', data: JSON.stringify(obj) });
// 读文本（必须是合法 UTF-8，否则 reject）
const text = await window.__DESK_PP__.invoke('skin_read_file', { path: 'data/cache.json' });
// 读二进制 → base64；写二进制 ← base64
const b64 = await window.__DESK_PP__.invoke('skin_read_file', { path: 'img.bin', binary: true });
await window.__DESK_PP__.invoke('skin_write_file', { path: 'img.bin', data: b64, binary: true });
// 列目录（path 缺省为皮肤根目录）
const entries = await window.__DESK_PP__.invoke('skin_list_dir', { path: 'data' });
// [{ name: "cache.json", is_dir: false, size: 123 }]
// 删除文件（仅限文件，不能删目录）
await window.__DESK_PP__.invoke('skin_delete_file', { path: 'data/cache.json' });
```

限制：

- `path` 一律相对皮肤目录：拒绝绝对路径、`..`、含冒号的路径段与符号链接逃逸；
- 读 ≤ 32MB，写 ≤ 16MB；
- `skin.json`、`settings.json`（含 `.bak` / `.tmp`）由应用管理——可读，禁止写入与删除（仅指皮肤根目录下这四个文件；子目录里的同名文件不受限）；
- 适合存皮肤自己的缓存/数据；皮肤目录随皮肤删除而删除，别拿它当持久仓库。

#### 注册表只读（权限 `registry`）

```js
const v = await window.__DESK_PP__.invoke('read_registry_value', {
  root: 'HKCU', path: 'Environment', name: 'TEMP'
});
// { kind: "expand_string", value: "%USERPROFILE%\\AppData\\Local\\Temp" }
```

- `root`：`HKCU` / `HKLM` / `HKCR` / `HKU`（也接受 `HKEY_CURRENT_USER` 等全名）；
- `kind`：`string` / `expand_string` / `multi_string`（值为数组）/ `dword` / `qword` / `binary`（值为 base64）；`qword` 以 JSON 数字返回，超过 2^53 会丢精度（实际罕见）；
- 只有读取接口，没有写入。键或值不存在时 reject。

#### 执行命令（权限 `shell`）

以普通权限（继承应用自身权限，不提升）、隐藏窗口执行，等待结束后返回输出：

```js
const r = await window.__DESK_PP__.invoke('run_command', {
  command: 'cmd', args: ['/c', 'ipconfig'], timeoutMs: 10000
});
// { code: 0, stdout: "...", stderr: "" }
```

- `timeoutMs`：默认 30000，钳制到 100–120000（毫秒，小数取整）；超时杀进程并 reject；
- `stdout` / `stderr` 各截断 1MB（截断不影响命令正常执行完）；中文 Windows 的 GBK 输出已自动转码；
- `code` 是进程退出码（异常退出可能为负数，如 -1073741819 = 0xC0000005）；
- 启动失败（命令不存在等）reject；
- 适合一次性查询类命令；需要交互的进程不适用；长驻进程的孙进程可能不会被超时清理，且孙进程持有输出管道时返回的输出可能不全，请谨慎使用。

#### 系统音量与媒体控制（权限 `system`）

```js
await window.__DESK_PP__.invoke('set_volume', { volumePct: 60 });  // 0–100，越界钳制
await window.__DESK_PP__.invoke('set_mute', { muted: true });

const ok = await window.__DESK_PP__.invoke('media_control', { action: 'play_pause' });
// action: play | pause | play_pause | next | previous
// 返回布尔：目标播放器是否接受了该操作；无播放会话时 reject
```

#### 剪贴板（权限 `clipboard`）

```js
const text = await window.__DESK_PP__.invoke('read_clipboard_text');
await window.__DESK_PP__.invoke('write_clipboard_text', { text: 'hello' });
```

仅文本。读取的是用户当前剪贴板——可能包含刚复制的敏感内容，请只在你明确需要时调用，这也是它单独要权限的原因。

#### 打开链接/文件（权限 `system`）

用系统默认程序打开（浏览器 / 文件关联）：

```js
await window.__DESK_PP__.invoke('open_external', { target: 'https://example.com' });
await window.__DESK_PP__.invoke('open_external', { target: 'D:\\docs\\report.pdf' });
```

允许的目标：`http(s)://`、`mailto:`、本机绝对路径（文件或文件夹）。明确拒绝：

- **可执行文件**（`.exe` `.bat` `.cmd` `.ps1` `.vbs` `.vbe` `.js` `.jse` `.wsf` `.wsh` `.msi` `.msp` `.msc` `.scr` `.com` `.pif` `.cpl` `.lnk` `.hta` `.reg` `.dll` `.jar` `.url`）——运行程序请走 `shell` 权限的 `run_command`，让用户对能力有正确预期；
- **UNC 路径**（`\\host\share` 形式，访问会触发 SMB 连接）；
- 相对路径与 `file:`、`javascript:` 等 scheme；
- 目标不存在与打开失败返回同样的错误，不区分。

#### 系统通知（权限 `system`）

弹出 Windows toast 通知（操作中心可见，来源显示为 Driftlet）：

```js
await window.__DESK_PP__.invoke('show_notification', { title: '提醒', body: '该喝水了' });
```

- `title` ≤ 64 字符、`body` ≤ 256 字符（超长截断），`body` 可省略；
- 没有按钮/回调等交互能力——它只是「提醒」；
- 首次调用会在开始菜单注册 Driftlet 的快捷方式（非打包应用发通知的系统要求），属正常现象；
- 请克制频率——用户被刷屏后会直接关掉整个应用的通知权限。

#### 麦克风频谱（权限 `mic`）

与 `get_audio_spectrum`（系统环回，免权限）同管线、同返回结构，但采集的是**麦克风输入**：

```js
const { bands, peak } = await window.__DESK_PP__.invoke('get_mic_spectrum', { bands: 32 });
```

无麦克风设备（或系统在隐私设置里禁用了桌面应用麦克风访问）时 reject；懒启动、闲置 30 秒自动释放设备，与环回一致。

### 5.4 设置读写命令（无需声明权限）

#### `skin_get_setting` —— 按 key 读自己的设置值

```js
const value = await window.__DESK_PP__.invoke('skin_get_setting', { key: 'api_key' });
```

- 只能读**自己 skin.json `settings` 里声明过的 key**；未声明的 key 会被拒绝；
- 返回该 key 的有效值（用户保存值，未保存时返回 schema 默认值）；
- 任何类型都可读——它是 **`password` 类型值的唯一读取通道**（§4.3）；普通类型用 `__DESK_PP__.settings` 更方便，无需走此命令；
- 身份取自窗口本身，皮肤无法读到其他皮肤的设置。

#### `skin_set_setting` —— 写自己的设置值

把某个自定义设置项的值写进自己文件夹的 `settings.json`，与管理器「皮肤设置」页共享同一份数据。用法与契约见 §4.4。

### 5.5 调用边界（皮肤调不到的命令）

`__DESK_PP__.invoke` 在技术上是直通转发，但**后端按调用窗口身份逐命令把关**：

- 管理器专属命令（安装/卸载/加载皮肤、修改窗口配置、修改全局设置、开机自启、预览截图等约 40 个）**仅管理器窗口可调用**——皮肤调用会被拒绝：`该命令仅允许管理器窗口调用`。不要尝试调用它们，也不要试图伪造身份（身份取自窗口本身，无法伪造）。
- 桥内部命令 `start_skin_drag` / `start_skin_resize` / `show_skin_context_menu` 由注入脚本在拖动/缩放点下和右键时使用，皮肤请勿直接调用。
- 皮肤实际可用的完整命令清单 = 本文档 §5.2–§5.4 列出的全部命令。未来版本新增能力时会同步更新本章。

## 6. 安全模型

Driftlet 的设计前提是：**皮肤是第三方编写的、能联网的本机代码**。平台在你（作者）与用户之间划了一条清晰的边界——本节说明平台强制了什么、不强制什么，以及你的责任。

### 6.1 平台强制的边界

| 边界 | 说明 |
|------|------|
| 管理器命令隔离 | 皮肤窗口调用任何管理器命令都会被后端拒绝（§5.5），皮肤无法安装/卸载/篡改其他皮肤或全局配置 |
| 权限声明 | 敏感能力（§5.3）必须在 skin.json 声明，且**安装时逐条展示给用户**（`shell`/`mic` 标高危）；未声明即拒绝 |
| 文件沙箱 | `files` 权限也只能读写皮肤自身目录（拒绝 `..`、绝对路径、冒号路径段、符号链接逃逸；读写有 32MB/16MB 上限）；`skin.json` 与用户 `settings.json` 对任何皮肤只读 |
| 设置隔离 | `settings.json` 永不通过 `skin://` 提供（含 8.3 短名、NTFS 流等变体），皮肤的设置值其他皮肤拿不到 |
| 密码保护 | `password` 类型设置值不注入任何页面（`__DESK_PP__.settings` 里恒为空串），只能由所属皮肤窗口经 `skin_get_setting` 读取 |
| 包安装防护 | `.dskin` 解压防路径穿越（zip-slip）、按实际解压字节限制总量（防 zip 炸弹）、限文件数、staging 失败回滚 |

### 6.2 皮肤能做什么（不被限制的）

- 完整的浏览器能力：DOM、Canvas、WebAudio、`fetch`/`WebSocket` 访问任意外部网络（跨域受目标服务器 CORS 约束，标签式加载不受限）；
- 与其他皮肤**同源**（`http://skin.localhost`）：可以请求到其他皮肤的普通资源文件（如图片）——这是协议设计使然，私密数据的防护由「设置隔离 + 密码保护」两条承担（§6.1），所以私密数据务必走 `password` 设置项，不要存成皮肤目录里的普通文件；
- 声明权限后获得对应本机能力（§5.3）。

### 6.3 作者的安全责任

平台管不到皮肤页面内部，以下责任在你：

- **防 XSS**：动态内容（用户输入、任务文本、网络返回）用 `textContent` 赋值或先转义再进 `innerHTML`——皮肤的设置值、任务清单都是用户可编辑的，直接拼 HTML 会被注入。示例皮肤 `controls-demo` 全程 `textContent` 渲染，是正确示范。
- **只加载自己信任的脚本与资源**：皮肤页面没有 CSP 保护，一个被劫持的 CDN 脚本就能拿到你的全部页面能力（包括已声明权限的命令通道）。资源尽量内置。
- **权限最小化**：只声明真正用到的权限——安装页会向用户展示声明列表，过度声明直接影响安装意愿与用户安全。
- **诚实声明用途**：在发布页说明每个权限的用途；`shell` 与 `mic` 会被标为高危。

## 7. 开发工作流与调试

### 7.1 三种安装方式

1. **开发期（推荐）**：把皮肤文件夹直接复制到 `<安装目录>\skins\`，管理器点「刷新」即出现，点「加载」运行。改完代码后右键皮肤 →「刷新皮肤」即时生效。
2. **管理器安装**：点「+ 添加皮肤」选择 `.dskin` 文件，弹出安装引导页（展示皮肤信息与权限声明），确认后安装。
3. **双击安装**：安装版注册了 `.dskin` 文件关联，双击皮肤包即唤起 Driftlet 并进入同一个安装引导页。

开发期也可以用命令行参数测试双击安装的完整链路：`npm run tauri dev -- -- "D:\path\x.dskin"`。

另外，debug 构建（`npm run tauri dev`）下可开启皮肤热重载：默认关闭，在设置页开启后，watcher 递归监视整个 skins 目录，已加载皮肤的文件变更防抖 300ms 后自动重载，无需手动右键刷新。

### 7.2 纯浏览器调试

皮肤本质是网页，布局/样式/大部分逻辑可以直接在浏览器（或 `npm run dev` 后的前端预览思路）里打开 `index.html` 调试：

- 桥不存在时 `window.__DESK_PP__` 为 `undefined`——所有访问带可选链 `?.` 并给默认值（§5），页面就能在无桥环境正常渲染；
- 需要模拟设置值时，在浏览器控制台手动赋值 `window.__DESK_PP__ = { settings: { ... } }` 即可；
- 依赖后端命令的部分（系统信息、文件读写）只能在管理器里实测。

### 7.3 排错清单

| 症状 | 先查 |
|------|------|
| 皮肤加载后空白 | 入口文件名是否与 `entry` 一致；资源引用是否用了 `skin://` 直写（应改相对路径，§3.1） |
| 样式/脚本静默不加载 | 同上——`skin://` 子资源在 Windows 不可解析，检查是否写成了绝对 `skin://` 形式 |
| 设置改了没反应 | 是否监听了 `desk-setting-changed`；`key` 是否与声明一致 |
| password 读出来是空串 | 这是设计——改用 `skin_get_setting`（§4.3） |
| 命令报错「未声明权限」 | 在 `skin.json` 的 `permissions` 补上对应权限后**刷新皮肤**（权限每次调用实时读取，无需重装） |
| 命令报错「仅允许管理器窗口调用」 | 你调了管理器专属命令——§5.5，换用文档列出的皮肤命令 |
| 窗口位置/大小与预期不符 | 以配置页「位置和大小」为准（逻辑像素）；检查是否有元素写死了超出窗口的尺寸 |
| 文件读写报「路径不合法」 | 路径必须相对皮肤目录，不能含 `..`、盘符、冒号 |

## 8. 打包分发（.dskin）

皮肤最终以一个 `.dskin` 文件分发给用户 —— 它就是一个 zip 压缩包。

### 8.1 用打包工具生成（推荐）

`tools/pack-skin.exe` 是**独立的免安装工具**（约 320 KB）——不需要安装 Driftlet、Node.js 或任何环境，把这个 exe 复制到任意位置即可用：

```
pack-skin.exe <皮肤文件夹> [输出目录]
:: 例：pack-skin.exe .\my-skin  →  当前目录生成 my-skin-1.0.0.dskin
```

打包前的校验与安装端**完全同一套规则**（skin.json 强类型解析、合法 `id`、入口文件存在、设置项类型合法），不通过会带行列号明确报错——打得出来就装得进去：

- 结构错误（如 `window.width` 写成字符串、设置项 `type` 不存在）直接拒绝并指出行列位置；
- 缺少 `version` 打印警告（不拦截，但更新判断会退化，建议补上）；
- 自动排除：`settings.json*`（用户数据）、`.git` / `.svn` / `node_modules` 目录、已有的 `*.dskin` 产物、`.DS_Store` / `Thumbs.db` / `desktop.ini`；
- 超上限直接拒绝：压缩包 64 MB / 解压后 256 MB / 5000 个文件。

源码在 `tools/pack-skin/`（Rust），`cargo build --release` 可重新构建。

### 8.2 手动打包

1. 确认 `skin.json` 已声明 `id` 与 `version`。
2. 把皮肤文件打成 zip：`skin.json` 放在压缩包**根目录**（或只套一层同名文件夹），不要把多个皮肤混在一个包里，不要包含 `settings.json`。
3. 把扩展名从 `.zip` 改成 `.dskin`（直接改名即可，内容不变）。

### 8.3 用户侧的安装/更新行为

- 两个入口（管理器「+ 添加皮肤」、双击 `.dskin`）共用同一个安装引导页：先校验是不是合法皮肤包（能否找到并解析 `skin.json`、`id` 是否存在、入口文件是否存在），不合法会明确提示原因；确认页展示皮肤名称、版本、作者、简介与**全部权限声明**（`shell`/`mic` 标高危）。
- 同 `id` 已安装时按版本号区分：更高版本 →「更新」、相同版本 →「覆盖重装」、更低版本 →「回退」，都会在确认页标明。
- **更新/重装/回退都保留用户的设置数据**：窗口配置按 `id` 存在全局 config.json，与皮肤文件解耦；「皮肤设置」页的用户值在皮肤文件夹的 `settings.json`，安装时先取出、替换后再写回（用户值优先于包内同名文件）。新增设置项用默认值，删除的设置项数据自动失效。
- `settings.json`（含 `.bak` / `.tmp`）是**用户数据，不应进入分发包**——`pack-skin.exe` 会自动排除；手动打包时也不要包含它（即使混入，安装时也会被用户已有值覆盖）。
- 正在运行的皮肤会被先卸载，更新/重装/回退后**保持卸载**——需要运行时由用户在管理器里重新加载（安装向导的「立即加载」也可以）。

## 9. 发布检查清单

打包前逐项过一遍：

- [ ] `skin.json` 声明了合法 `id`（小写字母/数字/中划线、非保留设备名）与 `version`
- [ ] `skin.json` 字段齐全（name / author / version / description），文件 < 1 MB
- [ ] 所有资源在皮肤文件夹内，**相对路径**引用；无外部 CDN 依赖（或已确认可接受离线降级）
- [ ] 透明背景下无不透明底色遮挡桌面
- [ ] 拖动区域使用 `.drag-region`，没有使用 `-webkit-app-region: drag`
- [ ] 在管理器里把窗口调小一半、放大一倍验证过：内容完整自适应，无裁剪、无窗口级滚动条（§3.3）
- [ ] 声明了 `settings` 的话：`key` 全唯一、类型正确（19 种之一）、`default` 与类型匹配
- [ ] 声明了 `"bilingual": true` 的话：分组内所有控件的 `group_en` 齐全（避免英文界面拆组），需要双语的字段都有对应 `*_en`（§4.5）
- [ ] 读取设置有默认值兜底（`?.` + `??`），监听 `desk-setting-changed` 实时应用
- [ ] `password` 类型值经 `skin_get_setting` 读取，没有依赖 `__DESK_PP__.settings` 里的值（恒为空串）
- [ ] 动态内容用 `textContent` 或转义后渲染，未把用户可编辑的值直接拼进 `innerHTML`（§6.3）
- [ ] 用到敏感接口的话：`permissions` 只声明实际用到的（§2.3），安装引导页展示的声明列表你自己看得过去
- [ ] 桥不存在的场景（纯浏览器打开）不抛错（`?.` 防御，§7.2）
- [ ] 提供 `preview.png` 或在管理器截取过预览
- [ ] 用 `pack-skin.exe` 打出 `.dskin`，并在管理器里实际安装/更新过一次验证（含权限声明展示）

仓库自带四个示例皮肤。`controls-demo` 是设置体系与页面规范的参考实现；`sys-monitor` / `media-hub` / `toolbox` 三个合起来覆盖皮肤可调用的全部 31 个后端命令（§5.2–§5.4），是接口调用的参考实现。强烈建议先读它们的代码再动手：

| 皮肤 | 演示内容 |
|------|----------|
| `examples/controls-demo` | 全部 19 种设置控件 + 分组 + 描述 + 中英双语（§4.5）、HTML/CSS/JS 拆分与相对路径引用、浅色海图 UI、填充+内部滚动范式、经相对路径 `fetch('skin.json')` 读取 schema 并按桥语言渲染控件标签/分组/选项、`desk-language-changed` 驱动界面语言跟随管理器即时切换（§4.5）、应用区实时应用设置值（主题色/进度条/状态点/字体/昼夜色调/面板密度）、`password` 类型经 `skin_get_setting` 读取、全程 DOM API / `textContent` 渲染 |
| `examples/sys-monitor` | §5.2 只读系统信息全家桶：CPU（总量条 + 每线程小竖条）/GPU/内存/磁盘（含指定卷）/网络（速率 + 本机 IP）/操作系统/进程 Top5（CPU、内存双排序）/电池/空闲时间/前台窗口/显示器；速率类 1 秒轮询（首调基线为 0）、静态信息启动读一次、页面隐藏暂停轮询。**零权限声明** |
| `examples/media-hub` | 音量读取/设置/静音、SMTC 媒体信息（封面/进度/状态）与播放控制（play_pause/next/previous）、系统环回与麦克风双数据源频谱（canvas 实时柱条 + 峰值线、页面隐藏暂停、停止轮询约 30 秒自动释放设备）、Toast 通知；权限 `system` + `mic` |
| `examples/toolbox` | 剪贴板读写、皮肤目录文件写/读/列/删、注册表只读（预设 + 自定义键）、执行命令（预设 `ver`/`ipconfig` + 自定义，展示 code/stdout/stderr）、打开链接（含 `.exe` 目标被拒绝的演示）、`skin_get_setting` / `skin_set_setting`（password 唯一读取通道、设置写回、管理器侧修改经 `desk-setting-changed` 同步）；权限 `files` / `registry` / `shell` / `clipboard` / `system` |

其中 `controls-demo` / `sys-monitor` / `media-hub` / `toolbox` 四个皮肤同样遵守：中英双语跟随管理器语言、动态内容全程 `textContent` / DOM API、桥缺失（纯浏览器打开）不抛错、命令 reject 的错误文案就地展示在对应卡片。

`controls-demo` 与 `sys-monitor` 不声明任何 `permissions`——它们用到的全部能力都是免权限的。
